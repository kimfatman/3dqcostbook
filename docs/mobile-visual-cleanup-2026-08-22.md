# 移动端视觉清理与390px复核记录

本轮继续收口移动端商业化视觉，重点去除会出现在有效页面上的网格和虚线纹理，并修复资料加载失败时落回浏览器默认按钮外观的问题。页面维持白色承载面、浅蓝环境底色、细实线分隔与克制阴影，经营数据、操作控件和少量说明文字的层级不变。

| 页面 | 390px复核结论 | 本轮处理 |
| --- | --- | --- |
| 首页 | 顶部店铺标识、通知入口、经营金额、轮播卡、图表预览与五项导航可见；首张宣传卡保持左文右图。 | 保持已完成的数字、Logo 与全幅轮播规则。 |
| 订单 | 月份筛选、空订单卡、售后入口和底部导航层级清楚。 | 未引入额外纹理或分隔装饰。 |
| 商品 | 搜索、成本卡行、金额列与风险标签保持紧凑可扫读。 | 未改变数据和下钻逻辑。 |
| 分析 | 图表、空态说明与列表行仍采用白色卡片和细实线。 | 网格仅保留在图表数据本身，不作为页面背景。 |
| 我的 | 账户、店铺管理、服务、皮肤与退出分区可辨。 | 去除不必要的页面纹理依赖。 |
| 个人与店铺资料错误态 | 加载失败时显示居中错误卡，重试与返回按钮具备主次层级。 | 新增 `.profile-load-state` 与 `.empty-state-actions` 的移动端样式。 |

登录入口的蓝色品牌首屏已从网格纹理改为柔和光晕。历史摘要、快捷入口、微趋势等承载面移除网格背景；归档和洞察路径的虚线改用细实线。构建后的自动化质量门禁通过 TypeScript 检查、25 个测试文件共 91 项测试及生产构建；构建仍保留既有主脚本体积提示。

本轮版本已同步腾讯云并完成生产健康验证：`https://api.3dq.site/healthz` 返回 `{"status":"ok"}`，`https://app.3dq.site/` 返回 HTTP 200；应用、反向代理和数据库容器均处于运行状态。因店铺资料和 Logo 取决于登录用户数据，真实店铺资产仍应由已登录用户在生产会话中完成最终目视确认。

补充生产匿名入口的 390px 复核：登录页在完成初始化后，蓝色品牌首屏、两层光晕、白色表单承载面、邮箱/密码输入与主按钮均完整可见；背景未出现网格或虚线纹理。该复核仅覆盖未登录入口，不涉及任何用户账户或业务数据。
