## 执行步骤

### 步骤1：Hero 区打磨
- 布局：品牌 Logo + 标语 + 简短价值描述（3 行以内）
- Logo：64×64 圆角 16px，居中或左对齐
- 标语：24px -0.02em text-primary，1 行
- 价值描述：14px text-secondary，2 行截断
- 背景：浅色渐变（bg-brand-soft 到 transparent），不使用深色 hero（避免文字不可读）
- 入场动画：fade-in + slide-up（400ms，延迟 100ms）

### 步骤2：表单输入框统一
- 所有输入框使用通用 Input 组件（批次12）
- 高度 44px，圆角 12px，边框 border-default
- focus：边框 action-primary + 4px 外发光（rgba(22,119,255,0.15)）
- error：边框 risk + 下方错误提示 12px risk
- 标签：14px text-primary，必填项加红色 *
- 前缀图标：16px text-secondary（邮箱/密码/店铺名）

### 步骤3：验证码按钮状态
- 默认："获取验证码"，ghost 按钮样式
- 点击后："发送中..."，disabled 状态，显示加载旋转
- 发送成功："60s 后重发"，倒计时，disabled
- 倒计时结束："重新获取"，恢复可点击
- 错误："重新获取"，error 样式，提示"验证码发送失败"
- 所有状态有明确的视觉反馈

### 步骤4：错误提示规范
- 位置：输入框下方，12px risk，左对齐
- 图标：左侧 12px 警告图标
- 内容：简洁明确（如"邮箱格式不正确"非"输入错误"）
- 出现时机：输入框失焦时验证，或提交时统一验证
- 消失时机：用户开始重新输入时消失
- 多个错误：依次显示，不堆叠

### 步骤5：密码强度指示器
- 位置：密码输入框下方
- 样式：4 段进度条，每段 25%
- 颜色：弱（risk 1段）/ 中（warning 2段）/ 强（success 3-4段）
- 文字：12px，"弱/中/强" + 建议（如"建议添加数字和符号"）
- 实时更新：用户输入时实时计算强度
- 注册页必须有，登录页不需要

### 步骤6：操作按钮统一
- 主按钮：primary 大按钮（48px 高度），full width
- 次按钮：ghost 按钮，如"忘记密码"
- 加载状态：显示旋转图标 + "登录中..."，disabled
- 禁用状态：opacity 0.5，cursor not-allowed
- :active：scale(0.98) + 背景加深
- 按钮下方："还没有账号？立即注册" / "已有账号？去登录"，14px，链接 action-primary

### 步骤7：社交登录与协议
- 社交登录按钮："微信登录" / "手机号登录"，outline 样式，full width
- 分隔线："或使用以下方式"，左右横线 + 中间文字，12px text-tertiary
- 协议勾选：复选框 + "我已阅读并同意《用户协议》和《隐私政策》"，12px text-secondary
- 未勾选协议时提交按钮 disabled
- 协议链接：action-primary，点击打开协议页面（新窗口或模态框）

## 常见问题与回退
- **问题：** 密码强度计算不准确
  **解决：** 使用简单规则（长度≥8 + 大小写 + 数字 + 符号），不引入复杂库
- **问题：** 验证码倒计时在页面切换后重置
  **解决：** 倒计时状态存储在全局状态或 localStorage，页面切换不丢失
- **回退：** `git revert` 本批次提交
