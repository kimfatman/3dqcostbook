# 首页经营信息架构：第一轮头脑风暴

## 核心判断

首页不应把“商品销量排行、利润排行、成本排行、销量预测”平铺成四张同等级卡片。商家打开首页首先需要回答的是：**本期是否在赚钱、销售是否在按预期推进、现在最该处理什么**。排行与预测是解释这一结论的证据，而不是与经营结果竞争首屏位置的独立目的。

> 首页的阅读顺序应是：**结果 → 动能 → 原因 → 行动**。其中“结果”回答赚没赚，“动能”回答能否完成本期，“原因”定位商品或成本，“行动”提供一跳下钻。

## 建议的信息优先级

| 优先级 | 商家问题 | 建议模块 | 首页形态 | 真实口径与下钻 |
|---|---|---|---|---|
| P0 | 本期有没有赚钱？ | 经营结果 | 保留现有“净营收 − 本月成本 ＝ 本期结果”主核算卡；增加订单数/销售件数的简短辅助信息 | 现有 `totals.revenue`、`totals.totalCost`、`totals.operatingProfit`；下钻报表/流水 |
| P1 | 销售节奏够不够？ | 销售动能与预测 | 一张紧凑的双指标卡：本期销售额/订单或销量，右侧为“按当前日均预计”的月末销售额 | 订单自然月聚合；下钻订单页。没有足够订单时必须显示“数据不足”，不生成预测 |
| P2 | 哪个商品在带来销量或利润？ | 商品经营榜 | **同一张卡内切换**“销量 / 利润 / 风险”三个视图，每次只显示 Top 3，避免三张排行榜重复 | `skuMetrics.soldQuantity`、`netRevenue`、`cogs`、真实毛利率；下钻商品成本卡或订单 |
| P3 | 哪类成本正在吞掉利润？ | 第一成本与成本变化 | 保留首页当前“第一成本”单行；增加“较上期变化”或“占本月成本”二选一，完整排行留在分析页 | `totals.categoryTotals`、`buildCategoryDeltas()`；下钻流水 |
| P4 | 有没有需要马上处理的例外？ | 优先风险 | 保留主核算卡中的唯一风险行动与顶部提醒；不再叠加常驻多张预警卡 | 预算、退款、低利润订单、风险成本卡的现有通知派生逻辑 |
| P5 | 产品宣传或广告 | Banner | 移至核心经营信息之后；只服务产品宣传/广告，不与经营结论争夺首屏 | 当前 Banner 配置 |

## 现有数据的可用性与边界

当前账本已经能够真实计算销量、订单、SKU 净营收、已售成本、毛利率、成本卡状态、成本分类、退款和订单利润预警。因此，**商品销量榜、商品利润榜、成本榜和运行率预测都可以实现，不需要伪造数据**。

需要避免两个口径错误。第一，商品“单位成本最高”不等于“总成本影响最大”；首页成本榜应优先展示成本分类占比或“成本上升的商品”，不能把单价当作总成本排行。第二，销售预测只能是基于当前录入订单的自然日运行率，必须标注“按当前日均”，并在订单覆盖不足时退化为补录引导；若未来增加销售目标，才可再加入“目标达成预测”。

## 推荐首页模块组合

```text
Logo + 经营提醒
行业 / 本期上下文
┌ 经营结果：净营收 − 本月成本 ＝ 本期结果 ┐
│ 销售额 · 订单数/销量 · 唯一优先风险          │
└───────────────────────────────────────┘
┌ 销售动能                                      ┐
│ 本期销售额 / 订单数      按日均预计月末销售额   │
└───────────────────────────────────────┘
┌ 商品经营榜  [销量] [利润] [风险]               ┐
│ 1. 商品 A   86 件 / ¥…      →                  │
│ 2. 商品 B   64 件 / ¥…      →                  │
│ 3. 商品 C   41 件 / ¥…      →                  │
└───────────────────────────────────────┘
第一成本：广告投放 49%  →
产品宣传 Banner
成本趋势（下沉为对比周期视图）
```

这套组合会把当前首页的 Banner 从第二位置后移，将成本趋势从“首屏主解释”改为“第二屏核对趋势”，同时新增销售动能和商品经营榜。这样既符合数据/图表优先，也避免销量、利润、成本、预测各自铺成大卡片导致首页重新膨胀。

## 建议的实施顺序

第一批只新增**销售动能卡**和**商品经营榜（默认销量）**，并把 Banner 后移；这些全部可基于现有订单、SKU 与账本指标派生。第二批补充“利润 / 风险”切换，以及销售运行率预测的数据不足状态。第三批如用户确有销售目标管理需求，再新增行业化销售目标和“目标达成预测”，但不应与预算混用。
