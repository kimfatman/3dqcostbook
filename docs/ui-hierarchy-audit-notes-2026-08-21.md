# 全界面层级审查：证据笔记

## 覆盖范围

本轮以 390px 视口审查五个一级入口（经营、订单、商品、分析、我的），以及消息中心、预算、流水、行业、报表、供应商、分类、SKU、记一笔、记录订单和新增商品。页面栈由 `tab + subPage` 控制，二级页面隐藏底部导航并统一使用返回按钮。

| 范围 | 当前主要任务 | 观察结论 |
|---|---|---|
| 经营 | 判断本期结果并处理风险 | “结果—原因—行动”最完整；Banner 未抢占核算主线。 |
| 订单 | 录入订单、筛选低利润与退款 | 空状态可行动，但顶部加号与底部“记录订单”重复；缺少行业化空状态和结果摘要。 |
| 商品 | 查看成本卡、单位成本、售价和单件利润 | 商品卡信息密度较好；SKU 成本的入口和独立页面编辑层级较弱。 |
| 分析 | 阅读利润、趋势与 Top 5 | 图表可用，但无收入时的行动入口不够突出；应先给经营判断再展示图表。 |
| 我的 | 行业、预算、报表、供应商、分类管理 | 管理入口清楚，但首屏更像导航壳，缺少一个明确的经营维护任务。 |
| 消息、预算与流水 | 下钻提醒、调整预算、核对分录 | 流水层级最清楚；预算的橙色占比过高；消息进入订单时与 Banner 的订单导航模式不一致。 |

## 初步问题清单

| 编号 | 级别 | 证据 | 对任务路径的影响 |
|---|---|---|---|
| H-01 | P0 | 消息中心 `openNotificationTarget()` 对订单使用 `goSub("orders")`；Banner 对订单使用 `setTab("orders")`。 | 同一个“查看订单”目的产生不同的底部导航与返回体验，用户无法形成稳定路径预期。 |
| H-02 | P0 | 供应商、分类列表的删除图标直接执行删除；成本卡删除才有 `window.confirm()`。 | 管理页中高风险动作的保护不一致，误触后仅靠状态反馈，缺少确认或撤销。 |
| H-03 | P1 | 订单空状态未使用行业图标、行业成本原因或账本公式，且上方加号与底部主按钮均新增订单。 | 首次录单页面同时存在重复操作和低品牌识别，无法快速解释“为什么现在要录”。 |
| H-04 | P1 | 记录订单表单在缺少 SKU 时仅显示空明细区；深链或状态异常时没有“先建商品成本卡”的引导。 | 用户到达订单录入页后可能不知道如何继续补齐前置数据。 |
| H-05 | P1 | 分析页与预算页有大图表/圆环，但分析无收入时的核心行动弱，预算以橙色形成页级主色。 | 二级页面不能始终按“结果—原因—行动”建立首屏判断，风险色压过品牌结构色。 |
| H-06 | P1 | “我的”首页以五项管理行作为主要内容，缺少当前待处理事项；报表列表也未突出本月草稿或待封存状态。 | 用户进入管理层后更像在浏览设置，无法直接完成当前经营维护任务。 |
| H-07 | P1 | 记录流水页的固定主按钮恒为“新增成本”，而页面同时覆盖收入、成本、退款。 | 固定动作名称预设了成本场景，弱化页面的多类型交易语义。 |
| H-08 | P2 | SKU 页面将成本更新嵌入稀疏列表；成本卡、SKU、定价三个入口分别承担关联任务。 | 已有能力完整，但“商品成本 → SKU → 订单”的学习成本偏高。 |
| H-09 | P2 | 订单、我的、商品、分析和管理列表有较多普通白卡。 | 品牌账本语言在首页与消息中心之外不够连续，跨页识别减弱。 |

## 保留项

首页经营判断簇、流水筛选与日期分组、成本卡单位经济结构、行业切换确认页、消息中心“结果—原因—行动”条目均应保留。审查建议将优先修复路径一致性与高风险动作，不改变账本口径、交易分录或行业模板数据结构。
