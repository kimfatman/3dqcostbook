UI 设计升级 · 技能选用建议

为「算得清 App 全局 UI 设计升级」筛选可用的 Agent 技能：扫描目录初筛 12 个候选，逐一读取 SKILL.md 确认真实能力，按项目栈（Tailwind 4 + 语义色令牌 + 移动优先产品 UI）映射。

核心 5 个辅助 3 个不推荐 3 个建议四步实施

核心推荐（5 个）

技能能力在算得清升级中的用法优先级
stitch::extract-design-md从现有代码库反向提取设计系统文档（组件/样式/Tailwind 配置/令牌 → DESIGN.md）第一步基线：生成「设计系统现状」与 docs/design-manual/ 手册对照，找「手册说的 vs 代码做的」差距第 1 步
color-palette从单一品牌色生成 11 阶色阶 + 语义令牌 + 深色变体 + WCAG 对比检查 + Tailwind v4 CSS用品牌蓝 #087ff5 生成完整色板，收编散落 CSS 的语义令牌（登录页对比度问题的根治方案）第 2 步
tailwind-design-systemTailwind v4 设计系统：CSS-first 配置、令牌、组件变体、响应式本项目正是 Tailwind 4——色阶落成 CSS-first 令牌与组件变体规范第 2 步
ui-ux-pro-max改进现有 UI/UX、设计令牌、组件规格、微文案、a11y、具体代码改动主工作流：覆盖全量审计 P1 遗留（洞察页渐进信息架构、流水扫描效率、二级表单统一）第 3 步
accessibility-reviewWCAG 2.1 AA 审计：对比度/键盘/触控目标/读屏升级后验收：全站系统化巡检（登录页发现的对比度/触控问题同类复查）第 4 步

辅助推荐（3 个）

技能用法备注
web-design-engineer桌面端左右分栏等高视觉页面改造实施 + 浏览器 QA设计工程师视角，React/HTML 产物
web-design-reviewer升级完成后视觉巡检回归（截图 + DOM 审计 + 修复）已在登录页评审验证好用
web-perf主 bundle >500kB 警告治理（Core Web Vitals：LCP/INP/CLS）依赖 Chrome DevTools MCP，本机 mcporter 为空需先配置

明确不推荐（3 个）

技能原因
frontend-page-design自述排除 dashboards/产品 UI/多步产品界面，专攻落地页作品集；算得清是产品 UI，不适配
motion-graphics动态文字/logo 动画属营销物料；产品内受 prefers-reduced-motion 约束价值低
muapi-ui-design生成高保真 mockup 需外部 muapi.ai API；项目已有明确设计语言与手册

建议实施顺序（四步，每步有验收）

1
基线提取（~0.5 天）

extract-design-md 生成 DESIGN.md 现状 → 与 docs/design-manual/ 手册逐项对照，输出差距清单

2
令牌系统化（~1 天）

color-palette（品牌蓝 #087ff5 色阶）+ tailwind-design-system（CSS-first 落地）→ 散落 CSS 语义令牌收编

3
页面级改造（2–3 天）

ui-ux-pro-max 按全量审计 P1 遗留逐页改造（洞察页/流水/二级表单），frontend-design 把质量关，web-design-engineer 做桌面分栏

4
三重验收（~1 天）

accessibility-review（WCAG AA 全站）+ web-design-reviewer（视觉回归）+ web-perf（bundle/Lighthouse）

执行引擎沿用既有闭环：pi + DeepSeek 逐卡实现 + 主线独立复验 + 三门禁 + Runbook 发布。输入基线：ui-ux-full-audit-2026-08-27（P0 已清、P1/P3 遗留）+ login-page-design-review（方案 A 已上线）+ docs/design-manual/ 设计手册。

决策待定

升级范围二选一：只做令牌系统化（第 1–2 步，~1 天）或 令牌 + 全站 P1 遗留改造（第 1–4 步，3–5 天）。web-perf 是否纳入取决于是否先配置 Chrome DevTools MCP。
