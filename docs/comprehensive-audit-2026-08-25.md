# 算得清全面项目审计

**审计版本：** `93e84541`（账单导出发布前检查点）  
**审计范围：** 经营流水与导出、账本数据保存、认证与媒体、移动端六个关键页面、依赖供应链、生产容器与反向代理。  
**审计结论：** 当前版本的核心路径已具备可用基础，自动化质量门禁与生产健康正常；但在**登录抗暴力破解、并发保存可靠性、依赖升级与生产防护头**方面存在优先级较高的工程风险，建议先完成 P0 再继续扩展业务功能。

| 项目 | 证据与结论 |
| --- | --- |

## 发现与优先级

| 优先级 | 发现 | 证据 | 风险 | 修复建议与验收标准 |
| --- | --- | --- | --- | --- |
| **P0** | 登录、注册和首次初始化没有速率限制、失败冷却、IP/账号维度告警或 CAPTCHA 阈值。 | `auth.login`、`registerAndCreateWorkspace`、`bootstrap` 均是公共过程；Caddy 未配置限流。 | 可被撞库、暴力猜测或批量注册消耗资源。 | 在反向代理和应用层加入分级限流、连续失败冷却、结构化安全审计；验证同 IP 与同邮箱达到阈值后被拒绝且不泄露账号存在性。 |
| **P0** | 账本保存采用“先读取 revision，再条件更新”的乐观锁，但未检查条件更新实际影响行数。 | `saveWorkspaceBook` 在更新 `workspaceBooks` 后直接写审计并返回 `conflict:false`。 | 两个并发保存窗口可能让后一请求未写入账本却向客户端报告成功，造成静默丢失修改。 | 将 `UPDATE ... revision = expectedRevision` 的受影响行数作为唯一成功条件；0 行时回滚审计写入并返回冲突。为双请求竞争增加集成回归。 |
| **P1** | 生产应用与 API 缺少 HSTS、CSP、X-Frame-Options/`frame-ancestors`、X-Content-Type-Options、Referrer-Policy 与 Permissions-Policy。 | Caddy 仅配置压缩与反向代理；公网响应头实测未包含上述策略。 | 增加点击劫持、MIME 嗅探与脚本注入后的影响面。 | 在 Caddy 增加最小安全头；以资源实际来源制定可工作的 CSP，并验证登录、媒体、静态素材与下载不被阻断。 |
| **P1** | 生产应用以 root 用户运行。 | `docker exec deploy-app-1 id` 返回 `uid=0(root)`；Dockerfile 未创建非特权用户。 | 一旦 Node 进程或依赖被利用，容器内权限过高。 | Dockerfile 建立只读/最小权限应用用户，使用 `USER nodeapp`；确认文件读取、构建产物与 COS 上传仍可用。 |
| **P1** | 依赖审计存在 19 条高危、47 条中危、8 条低危通告；直接生产依赖包含过期 `axios`、`nanoid`、`drizzle-orm`，新增 `xlsx@0.18.5` 本身没有可用修复。 | `pnpm audit --prod`；高危包还包括间接 `lodash`、`path-to-regexp`、`form-data`。 | 供应链与运行时攻击面扩大；其中 Axios 用于服务端 SDK，Drizzle 用于数据访问。 | 建立可升级矩阵：先升级有兼容修复的直接依赖和 Express 链；评估用维护中的 XLSX 写入库替代 SheetJS 社区版或隔离其输入面；每批升级跑全量测试与生产构建。 |
| **P1** | 全局 JSON/URL 编码请求体上限为 50MB，且无通用请求速率/负载防护。 | `server/_core/index.ts` 在所有路由前使用 `express.json({ limit: "50mb" })`。 | 未认证端点也需解析大请求，放大内存和 DoS 风险。 | 将认证与 tRPC 的 JSON 上限降至合理值（例如 1MB），媒体继续由专用 5MB raw 路由处理；增加 413 和限流回归。 |
| **P1** | OAuth 模块在生产日志持续输出 `OAUTH_SERVER_URL is not configured`。 | 最近 300 条应用日志出现该错误，当前自托管认证仍可运行。 | 混淆故障监控，并暗示未使用模板模块仍参与启动。 | 在自托管模式禁用未使用 OAuth 初始化，或补齐有意配置；生产日志在冷启动后不应出现 ERROR。 |
| **P1** | 账单导出已在本地浏览器完成真实下载，但已登录生产会话下载仍未验收。 | 本地下载文件被识别为 UTF-8 BOM CSV 与 Microsoft Excel 2007+；生产当前仅完成 API/HTTPS/容器健康检查。 | 生产 Cookie、下载策略或浏览器行为仍可能与开发环境不同。 | 登录生产后分别导出 CSV/XLSX，记录文件名、类型、筛选笔数与空结果提示；不修改真实账本数据。 |
| **P2** | 首页经营结果为正值时，“近 7 日销售走势”可能显示 `¥0` 与平直线。 | 390px 截图中经营利润和成本公式有值，但趋势卡为零。 | 用户可能误读为数据异常，削弱首页可信度。 | 区分“没有日粒度交易”与“值为零”；显示明确空态/补录入口，或从真实日交易聚合趋势。 |
| **P2** | 个人中心存在三种高装饰主题皮肤，与当前统一商业化数据界面产生风格分裂。 | 390px“我的”页显示柔光材质、极光玻璃、深海展示舱。 | 品牌认知分散，且增加后续视觉回归成本。 | 保留一个默认数据主题；如保留个性化，仅支持密度与浅深偏好，并为主题切换建立视觉回归。 |
| **P2** | 流水页长列表的数据密度高，但缺少粘性筛选汇总、分页/虚拟滚动及导出结果的更明确摘要。 | 390px 全量流水为 63 笔，滚动长度较长；筛选已支持但列表持续渲染。 | 数据增长后影响性能与单手浏览效率。 | 在 200+ 条数据基准下测量渲染与滚动；引入按月折叠、虚拟列表或增量加载，并显示“当前筛选条件 + 导出笔数”。 |
| **P2** | 测试覆盖以领域纯函数和主要 HTTP 路由为主，`saveWorkspaceBook` 并发、登录节流、生产安全头、浏览器下载与登录输入故障均无自动化覆盖。 | 27 个测试文件覆盖 98 项；`server/db.ts`、`server/routers.ts` 缺相邻测试。 | 关键跨层回归需依赖手工检查。 | 增加 API 集成测试、并发保存测试、Playwright/浏览器下载测试与安全头断言；将生产 smoke test 固化为发布门禁。 |

## 功能与交互审计结论

核心账本、订单/SKU、退款、成本卡、供应商、分类、预算、月报和图表路径均已有领域测试与移动端入口。流水筛选、月份、关键词和导出使用同一当前结果集合；导出字段覆盖日期、类型、分类、金额、供应商、渠道、订单、备注、凭证、状态与流水编号。账期增长系数越界曾导致演示数据出现无效金额，本轮已补回退和初始化修复，相关测试通过。

需要特别注意的是：当前账本主体仍以工作区 JSON 状态保存。该方案便于快速演进，但会使“单条流水级并发、审计、查询性能、精细权限”依赖客户端状态与整本 revision。应先修正 revision 条件更新的原子性，再决定是否将高频流水和订单拆表。

## 视觉与可用性审计结论

当前移动端已形成稳定的白色承载面、蓝色经营结果卡、金融数字等宽字体、紧凑列表和五项底部导航。首页、流水、分析与我的页的信息任务总体可区分；资料读取失败时也有明确重试与返回出口。

后续视觉优化应优先解决数据可信度与长列表效率，不建议重新引入页面网格、装饰性虚线或厚重分隔。首页趋势在没有日数据时需要明确的业务空态；个人中心的主题功能则应收敛，避免与核心经营数据界面产生割裂。

## 建议修复顺序

| 顺序 | 批次 | 目标 |
| --- | --- | --- |
| 1 | 安全与数据完整性 | 登录限流/冷却、账本条件更新原子性、请求体限额。 |
| 2 | 供应链与边界防护 | 依赖升级/替换计划、Caddy 安全头、非 root 容器、OAuth 启动日志收口。 |
| 3 | 经营可信度与性能 | 首页日趋势空态、流水大列表基准与增量加载、生产导出真实验收。 |
| 4 | 自动化门禁 | 并发保存、登录节流、安全头、真实浏览器下载与移动端输入回归。 |

> 本报告的生产环境核查仅进行健康、响应头、匿名路由和容器状态观察；未读取密码、密钥、数据库明文或真实用户账单内容。生产账单下载与用户设备输入问题被明确列为待验收，而非宣称已通过。
