## P1 · 应立即修复

### P1-1 分析脚本占位符未解析，全站每页报 HTTP2 协议错误

- **页面/文件**：全站；`client/index.html` 第 14 行
- **证据**：Playwright 六个页面上下文全部捕获 `GET https://app.3dq.site/%VITE_ANALYTICS_ENDPOINT%/umami :: net::ERR_HTTP2_PROTOCOL_ERROR`
- **根因**：`<script defer src="%VITE_ANALYTICS_ENDPOINT%/umami" data-website-id="%VITE_ANALYTICS_WEBSITE_ID%">` 使用 CRA/Vue CLI 风格的 `%VAR%` 占位符（继承自 project template，`template.json` 同款），**Vite 构建不替换该语法**，原样进入产物
- **影响**：浏览器每次加载都请求非法 URL（控制台错误污染排障）；umami 访问分析完全失效，运营无数据
- **修复建议**：接入 umami 前直接移除该行；接入时改用 `import.meta.env.VITE_ANALYTICS_ENDPOINT`（vite define 或构建期 HTML 转换），并保证未配置时整段脚本不输出

### P1-2 登录方式三 Tab 平铺拥挤，触控热区不足

- **页面**：登录（密码登录模式）`.selfhost-methods`
- **证据**：DOM 实测三 Tab 高度 34px、字号 11px（390px 视口）；视觉评审判定「过于拥挤、文字压缩折行风险、点击热区过小」
- **影响**：老年/大手指用户误触率高；三个并列验证方式让首次用户困惑
- **修复建议**：Tab 合并为「密码登录 / 验证码登录」两个维度（验证码 Tab 内再选邮箱或短信），Tab 高度提升至 ≥44px

## 做得好的（改造时保留）

1. **品牌语义呼应**：「算得清 ↔ 每一笔成本都算得清楚」直击商家「怕账目混不清」痛点（视觉评审点名表扬）
2. **信任信号**：「安全登录」chip、CloudBase 验证码来源说明、hero 副语
3. **状态可辨**：Tab 选中态色块清晰；Filled 式输入框触控面积大、与整体圆角语言一致
4. **可访问性基础扎实**：autocomplete 全套（email/current-password/new-password/name/one-time-code/tel）、`required`、`role="alert"` 错误提示、label 包裹、`inputMode`/`one-time-code` 支持 SMS 自动填充
5. **安全与流程**：OTP 全流程（邮箱/短信）+ 60s 冷却 + 10 分钟有效期提示 + 通用错误文案不泄露账号存在性（对应 08-25 安全批次要求）

> 测量方法披露：对比度采用「文字色 vs 最近非透明祖先背景」近似计算；深蓝面板内白字的 1.07 读数是近似算法未穿透到深色底的假阳性，已从结论中剔除，仅采信浅底文字的读数。
