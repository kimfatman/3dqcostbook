# 经营流水页移动端重排复核

本轮以用户提供的 Android 浏览器截图为问题基准。原页面同时挂载了 `RecordsPage` 内的导出卡与根级 `RecordExportActions`，导致同一筛选结果出现两次导出承载面；页面标题“经营流水”也在子页导航与内容区重复出现。

参考移动端金融产品的“**先筛选并核对列表，再从同一列表上下文导出**”模式，导出不再独立占用第二张卡片。Lili 将筛选后的导出放在交易列表右上角，并明确文件与当前筛选一致；Skwad 的移动端也以当前筛选结果作为导出范围。[1][2] 本页因此采用“筛选 → 搜索 → 结果数/单一导出栏 → 列表或空态”的单一流线。无匹配时不展示不可用的导出操作，只提供一个“清除筛选”恢复动作，符合 Intuit 对搜索/筛选空态保持简短、清晰且可行动的建议。[3]

| 验收项 | 375px | 390px | 结论 |
|---|---:|---:|---|
| 标题层级 | 已复核 | 已复核 | 子页导航保留“经营流水”，内容区只显示任务标题，去除重复标签。 |
| 筛选与搜索 | 已复核 | 已复核 | 类型筛选、月份与搜索输入保持一条连续操作区，未见横向页面溢出。 |
| 导出承载面 | 已复核 | 已复核 | 有结果时仅显示一处“当前筛选 / 笔数 / CSV / Excel”紧凑导出栏。 |
| 列表与悬浮操作 | 已复核 | 已复核 | 金额列、记录行和悬浮“记一笔”均保留原有操作与安全区。 |

随后在 430px 有数据状态和 390px 无匹配状态补充复核。430px 下导出栏仍与结果数保持同一行节奏；390px 无匹配状态仅显示短标题、单句恢复提示和“清除筛选”，不显示禁用导出按钮或第二张导出卡。截图级结论与真实 DOM 回归一致。
