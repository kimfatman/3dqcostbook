# 全局 UI/UX 设计优化方案
**版本：** v1 ｜ **日期：** 2026-08-31 ｜ **方法：** 全局优化研究报告审计 × `ui-ux-pro-max` 设计规则库 × `apple-design` 流体交互规范 × 现有 `DESIGN.md` 令牌基线交叉适配
**目标：** 把研究报告的 12 页审计发现 + skill 规则库收敛成一套**可直接实施**的全局 UI/UX 优化方案，全部落在现有 `--sdq-*` 令牌基线上，不推翻 C1–C7 已上线成果。
**引用 skill：** 本地已安装 `ui-ux-pro-max`（79 样式/192 配色/74 字体/119 UX 规则/25 图表/22 栈）与 `apple-design`（Apple 流体交互），下文中 `[U1]…` 标注规则来源编号。

---

## 一、总体判断与原则

研究报告一句话评价："成本计算极其专业、UI 表现参差不齐"。现有 `DESIGN.md` 基线已沉淀 `--sdq-*` 语义令牌（light/deep/aurora 三皮肤）、原色阶方法论、金融数字字体，C1–C7 已上线。**本轮不是推倒重来，而是"补缺口 + 定标准 + 修阻断"**：

| 原则 | 说明 |
|---|---|
| 令牌优先 | 一切新样式只写语义令牌，禁止新硬编码 hex；`ui-ux-pro-max` 规则 §6 `raw hex in components` 明确禁止 |
| 移动优先 | 触控 ≥44pt/48dp、安全区、8dp 节奏、375px 回归 [U-pro] |
| 流体而非动画堆砌 | 动效遵循 apple-design：响应于按压、可中断、弹簧、reduced-motion；只动 transform/opacity [U-pro §7] |
| 数据可视化语义化 | 图表不依赖单一颜色表达含义（颜色+符号+文本）[U-pro §10] |
| 双主题贯穿 | light/deep 对比度各自独立校验，不假设亮色值可直接带入暗色 [U-pro pro-rules] |

## 二、设计系统层（token 收敛与体系化）

### 2.1 颜色：77 色 → 语义令牌（现状已部分完成，收尾）
研究报告审计 77 种 distinctColor；`DESIGN.md` 已用 `color-palette` 方法论把品牌蓝 4 变体 + 灰系 10+ 近似值收编为 11 阶原色阶（blue-500/600/950、neutral-500/600/900）。**剩余动作：**

| 项 | 方案 | 规则依据 |
|---|---|---|
| 深蓝/亮蓝语义固化 | 深蓝 `blue-950/700` = 已确认/历史/数据快照；亮蓝 `blue-500/600` = 操作/进行中/强调 | 报告 P1-B |
| 语义色下沉组件 | `--sdq-income/cost/profit/risk/info` 已具备，检查是否全组件透传 | DESIGN.md §5 |
| 双主题对比度门禁 | light/deep 各自 ≥4.5:1 正文；分隔线两主题均可见 | [U-pro pro-rules Light/Dark] |

### 2.2 字号：10 档断档 → 11 档体系
研究报告实测 8/9/10/11/12/14/15/16/17/39，断档在 17→39。按报告建议落 `--sdq-text-*`：

| Token | px | 用途 |
|---|---|---|
| caption | 11 | 辅助、时间戳 |
| small | 12 | 标签 |
| body | 14 | 正文（移动端 16→14 收敛） |
| body-lg | 16 | 重要正文 |
| subhead | 18 | 卡片标题 |
| h3 | 20 | 区块标题 |
| h2 | 24 | 页面小标题 |
| h1 | 30 | 页面大标题 |
| display | 36 | 关键经营数字（毛利率/保本/客流） |
| hero | 48 | 经营概览 ¥（替代 39） |

金融数字统一 `IBM Plex Mono + tabular-nums`（已接入，保持）。

### 2.3 圆角/按钮/阴影：收敛为令牌
| 体系 | 收敛值 | 说明 |
|---|---|---|
| 圆角 13→8 档 | 0/4/8/12/16/24/9999/50% | 现有 7/9/10/11/17 归入最近档 [报告 §2.3] |
| 按钮 5 档高 | xs24/sm32/md40/lg48/xl56 + FAB56圆形 | 现有 22/30/32/44/46/54 收敛 [报告 §2.4] |
| 阴影 4 档 | xs/sm/md/fab（蓝调统一） | 已统一蓝调，收敛层级 [报告 §2.5] |

### 2.4 图标：SVG 非 emoji、一致性
研究报告发现 emoji+SVG 混用。执行 `ui-ux-pro-max` 图标纪律 [U-pro pro-rules Icons]：
- 结构化图标（导航/设置/系统控件）一律 SVG（Lucide 系），禁止 emoji
- 图标尺寸走 token（icon-sm/md/lg），同一层级统一描边粗细、统一填充/线性风格
- 纯图标按钮必须有 aria-label；装饰性图标 `aria-hidden`
- 图标与邻接文本对比度 ≥3:1

### 2.5 暗色模式：双轨 token（报告 P2 预留，本轮先建机制）
现有 `skin-deep` 皮肤令牌完整。本轮确认：所有新组件按"语义 token 双轨"书写，暗色对比度独立校验（正文 ≥4.5:1、非文本 ≥3:1），分隔线/状态在双主题都可见 [U-pro pro-rules]。

## 三、交互层（apple-design 流体交互适配）

研究报告对动效无系统化要求；`apple-design` 提供 Apple 流体规范，抽取适配到本产品（财务工具，动效克制）：

| 原则 | 落地 | 依据 |
|---|---|---|
| 响应于按压 | 按钮/卡片 `:active` 立即反馈（scale 0.97，100ms），不等 release | apple-design §1 |
| 可中断动画 | 抽屉/展开/翻页动画随时可反向抓取，绝不锁输入 | apple-design §3 |
| 弹簧而非线性 | 进入用 deceleration、退出用 acceleration；退场时长为入场 60–70% | [U-pro §7 easing/exit] |
| 只动 transform/opacity | 禁用 width/height/top/left 动画，避免 CLS | [U-pro §7 transform-performance] |
| 一屏最多 1–2 个动效 | 财务数字不做多余动画；数字稳定态优先 | [U-pro §7 excessive-motion] |
| reduced-motion 全关 | 尊重系统偏好，关闭非必要动效 | [U-pro §7] |
| 触控目标 | 图标/按钮热区 ≥44pt(iOS)/48dp(Android)，视觉小则扩热区；热区不因动效移位 | [U-pro pro-rules Touch] |
| 按压反馈 | 80–150ms 内给 ripple/opacity/elevation 反馈 | [U-pro pro-rules Interaction] |

## 四、导航与信息架构（报告 P0-B 核心修复）

研究报告 P0-B：详情页无主导航、跨模块跳转断裂。对齐 skill 导航规则：

| 项 | 方案 | 规则依据 |
|---|---|---|
| 粘性主 Tab | 详情页保留底部主 Tab（工作台/订单/商品/洞察/我的），FAB 在详情页隐藏 | [U-pro §9 persistent-nav] |
| 底部导航 ≤5 项 | 现 5 Tab 合规；图标+文字双标注；选中态高亮（色+字重+指示） | [U-pro §9 bottom-nav-limit/nav-label-icon/nav-state-active] |
| 次级导航条件化 | 长内容页用"分段控件/次级 Tab"（基本信息/成本明细/…） | 报告 4.3 方案 |
| back 行为 | 返回保留滚动/筛选/输入状态；支持系统手势返回 | [U-pro §9 back-behavior/state-preservation/gesture-nav-support] |
| 深链接 | 关键页可用 URL 深链恢复（现有 `?screen=` 已具备，保持） | [U-pro §9 deep-linking] |
| 破坏性操作分离 | 退出登录从红色描边改中性动作，视觉/空间上与非破坏项分离 | 报告 P1 + [U-pro §9 destructive-nav-separation] |
| 空导航态 | 导航目的地不可用时解释原因，不静默隐藏 | [U-pro §9 empty-nav-state] |

### FAB 修复（报告 P0-A）
- 方案 A：FAB 上移 64px（高于底部 Tab），滚动容器 `padding-bottom: 96px`
- FAB 语义按页面变化：洞察/经营分析页引导"记订单"，商品页引导"记商品"
- 不与 Tab 冲突时不显示 FAB 于详情页

## 五、组件与页面专项（研究报告 12 页问题落点）

### 5.1 全局组件（报告建议 12 个，对齐现有 ui/ 库）
现有 `components/ui/` 已含大部分 shadcn 组件。补齐缺失语义组件：`MetricCard`（大数字+标签+趋势）、`EmptyState`（统一插画+行动）、`PageHeader`（返回+标题+操作）、`FAB`（智能位置避让）、`SegmentedControl` 收敛。经营分析/新页面一律走这些组件，不写页面私有样式。

### 5.2 图表规范（利润瀑布图，报告 P1）
研究报告：瀑布图无图例、只用蓝+深蓝+灰、底部被 FAB 遮挡。按 skill 图表规则 [U-pro §10]：
- 瀑布图适用 4–12 根柱；超 12 聚合为"其他"
- 增减配 **颜色+符号/方向图标**，不单靠红绿表达（财务工具无障碍重点）
- 图例齐全；hover/焦点显示同一数值（键盘可达）
- 增加 `#4CAF50`/减少 `#F44336`/起 `#2196F3`/终 `#0D47A1` 语义色，与现有 `--sdq-*` 对齐后落令牌

### 5.3 表单反馈（报告 P1-2 输入受控 bug + skill 表单规则）
- 表单用 uncontrolled + onBlur 提交，规避"受控追加 bug"（经营分析模块直接采用）
- 错误内联在字段下方并 `aria-describedby` 关联；不只顶部总错误 [U-pro §8]
- 占位符不能替代 label；label 可见 [U-pro §8]

### 5.4 状态与空态
| 场景 | 方案 |
|---|---|
| 暂无上期基线 | 蓝色「待观察」标签 + 灰底说明 + "如何积累基线"内联帮助（替代红色徽章，报告 P1-A） |
| 空列表 | EmptyState：结果/原因/主行动三件套（订单/物料/套餐/洞察） |
| 加载 | 骨架屏预留空间，防 CLS [U-pro §3] |

### 5.5 各页面专项修复清单（报告 §3 逐页）
| 页面 | 严重度 | 修复 |
|---|---|---|
| 工作台 | P1/P2 | 经营概览卡"白色矩形"补样式；"回款额"标签不被柱图遮挡；事件明细空白收敛；"全部"链接补箭头 |
| 订单列表 | P1/P2 | "全部"Tab 选中态加深；批量工具条悬浮改内联；卡片右侧补信息密度/快捷操作 |
| 商品成本卡 | P1/P2 | 标题"商品成本卡"→语义更宽（商品管理）；补库存/SKU/最近成交；成本上升徽章警示性加强 |
| 洞察 | P0/P1/P2 | 瀑布图底部不被 FAB 遮挡；补图例；蓝色大卡与工作台错开；日期范围扩季度/自定义 |
| 商品详情 | P0 | "商品商品成本详情"→"商品成本详情"（去重字）；"更多"按钮权重对齐主 CTA |
| 订单详情 | P1/P2 | 深蓝卡颜色与商品详情一致；空"退款退货回收"卡收敛为空态行 |
| 消息中心 | P1/P2 | 补时间戳；右侧留白收敛；顶边颜色编码配文字标签 |
| 我的 | P0/P1/P2 | 经营行业补齐模板切换（对齐 D2 七套主推）；退出登录改中性色；头像与品牌色关联；预算规则解释 |
| 智能定价 | P1 | 滑块蓝色轨迹在深蓝卡上提对比；成本/建议两线颜色区分；保存模板位置归位 |

## 六、实施优先级（对齐研究报告路线图 + 现有 C1–C7 节奏）

| 阶段 | 范围 | 规模 |
|---|---|---|
| **P0（1–2 周）** | FAB 避让（P0-A）、详情页主导航（P0-B）、"商品商品成本详情"文案、OTP/店铺切换器（后端已有排查） | 3.5–5 天 |
| **P1（1–2 月）** | 详情页粘性 Tab+内容栈；设计 token 全量下沉（字号/圆角/按钮/图标）；输入 bug 修复；瀑布图规范；红徽章→蓝标签；经营分析一期（4 卡，14 天）；一单多品+成本快照 | 37 天 |
| **P2（3–6 月）** | 暗色模式双轨；PWA；路径路由；行业模板 7 套（21 天）；数据导入导出；RUM | 60 天 |

**落地顺序建议**：P0 修复先做（独立小步、易验收）→ 设计 token 下沉与经营分析一期并行（经营分析按本方案规范实施，反向驱动全站收敛）。

## 七、验收清单（交付前逐项过）

**process（skill 规范）**
- [ ] 375px 小屏 + 横屏均测
- [ ] reduced-motion 开启下无异常
- [ ] 暗色模式对比度独立校验（正文 ≥4.5:1、非文本 ≥3:1）
- [ ] 触控热区 ≥44pt/48dp
- [ ] 无内容被固定栏/安全区遮挡（FAB/Tab 均不遮内容）

- [ ] 无 emoji 当图标；图标统一 Lucide 族、统一描边/填充

- [ ] 分隔线双主题可见
