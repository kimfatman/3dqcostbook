# 成本分析页面重排解决方案

**版本：**方案稿 v1  
**目标：**让用户在 3 秒内回答三个问题：**本期成本是否异常、主要由什么造成、下一步点哪里核对。**  
**不变约束：**金额以分存储并按两位小数展示；净成本、正向成本、成本回冲、上期基线、分类排序、供应商真实关联及所有流水下钻保持现有定义。[1]

## 一、设计结论

成本分析页不需要新增更多指标，而需要将现有数据重新编排为单条决策路径：

> **结论 → 最大原因 → 行动 → 结构 → 变化 → 风险/归属**

当前饼图、分组柱、利润桥、趋势、行业漏损和供应商排行均保留；本方案只调整它们的**出现顺序、可见数量、信息密度和行动表达**。首屏不再把“图表”和“结论”当作两个并列模块，而是让一张结论卡直接指向最大的真实成本分类。

| 层级 | 用户问题 | 首选表现 | 数据来源 | 主操作 |
|---|---|---|---|---|
| 1. 结论 | 本期花了多少、变化是否异常？ | 结论卡 | `costSummary.totalCost`、`delta`、`deltaRate` | 切换本月/上月 |
| 2. 原因 | 最大成本来自哪里？ | 结论卡中的原因行 | `costSummary.structure[0]` | 下钻该分类流水 |
| 3. 结构 | 钱主要花到哪些类别？ | 饼图 + 前 3 个图例 | `costSummary.structure`、`grossCost` | 点类别/查看全部 |
| 4. 变化 | 哪些类别的占比变了？ | 精简分组柱财务列 | `buildCostStructureComparison` | 下钻该期分类 |
| 5. 风险 | 是否需要继续复核？ | 摘要型折叠入口 | 现有利润桥、趋势、隐形成本 | 展开详情 |
| 6. 归属 | 支出是否有供应商归属？ | 供应商排行或单行空态 | `buildSupplierCostRankings` | 看供应商流水/记支出 |

## 二、推荐页面结构

### 1. 首屏：结论、原因和操作合为一张卡

首卡保留“本月/上月”切换，但改用三段结构。金额仍是视觉主角；其下的比较行仅显示真实环比；最下方以可点击行直接呈现最大分类。这样用户无需先阅读饼图就能知道要处理什么。

```text
成本分析 · 2026 年 08 月                         [本月 | 上月]

┌──────────────────────────────────────────────┐
│ 已入账净成本                                  │
│ ¥138,640.00                                   │
│ 较上期 +¥0.00 · 持平                          │
│ ──────────────────────────────────────────── │
│ 最大原因  商品采购 · 40.8%      [核对流水  ›] │
└──────────────────────────────────────────────┘
```

当存在成本回冲时，金额下方仅增加一行等式，而不新增卡片：

```text
正向成本 ¥146,000.00 − 回冲 ¥7,360.00 = 净成本 ¥138,640.00
```

当上期不存在时，比较行改为“暂无上期基线”，不显示伪造的 0% 或变化箭头。当前分类、金额和流水下钻仍完全复用既有聚合与回调。[1]

### 2. 结构区：饼图只回答“本期钱花到哪里”

结构区标题固定为**“本期钱花在哪里”**，避免与上方“成本结论”重复。饼图中心显示正向成本金额；右侧或下方只默认显示前 3 个分类。第 4 项及以后进入“其他 N 类”入口，避免 375px 视口出现五到六行密集标签。

| 元素 | 展示规则 | 行为 |
|---|---|---|
| 饼图中心 | 正向成本金额；存在回冲时以小字提示“净成本已扣除回冲” | 不强制将扇区做成小点击目标 |
| 前 3 图例 | 色点、分类、金额、占比等宽对齐 | 点击进入该分类当期流水 |
| 其他 N 类 | 仅在第 4 项及以后存在时显示 | 点击打开当前期间全部成本流水 |
| 底部洞察 | “最大项 商品采购 40.8%” | 与首卡一致，但不重复操作文案 |

这一处理保留了饼图对“构成”的优势，同时避免它承担变化比较或全量列表功能。

### 3. 变化区：分组柱只回答“哪些类别变了”

将模块改名为**“哪些成本占比变了”**。默认只展示按 `abs(shareDelta)` 排序的前三项；用户通过“查看全部对比”展开其余真实分类。每行使用固定财务列，而不是让用户在柱、文字与变化值之间反复来回读取。

```text
哪些成本占比变了                         本期  上期
商品采购         40.8%  40.8%   [▮▮][▮▮]  持平   ›
平台佣金         16.6%  10.0%   [▮  ][▮ ] +6.6pt ›
广告投放         13.4%   8.0%   [▮ ][▮  ] +5.4pt ›
                                      查看全部对比
```

其中蓝色恒为本期、橙色恒为上期；变化值是唯一的风险色来源。`0pt` 改为“持平”，降低无意义数字噪声。上期为零时保留橙色零柱与“上期 0%”的真实文字，不推断或补齐历史值。[1]

### 4. 趋势与风险：折叠入口应先给一条真实摘要

现有详情仍保留利润桥、近 6 月收入与成本、行业隐形成本。变化的是折叠入口：它不再只写泛化的“趋势与风险复核”，而是基于已有真实计算状态给出一句摘要。

| 已有状态 | 入口摘要示例 | 展开后保留内容 |
|---|---|---|
| 有上期且最大分类上升 | `商品采购占比上升 6.6pt` | 利润桥、月度趋势、行业漏损 |
| 有成本但无上期 | `已有成本，暂无上期基线` | 同上；对比内容按空态说明 |
| 无销售收入 | `尚未录入销售收入，利润图待生成` | 保留补录收入操作 |
| 无可估算基数 | `隐形成本待补收入或成本基数` | 保留当前边界说明 |

摘要只能引用已有的 `priority`、`deltaRate`、结构对比和可用性状态；不得引入“预测”“异常概率”等新模型。

### 5. 供应商归属：从完整空卡收束为行动行

有真实关联支出时，供应商排行维持棒棒糖排行，但最多展示前三名并提供“查看全部”。无关联支出时压缩为一行：

```text
供应商归属    暂无已关联支出       [记录支出并关联供应商 ›]
```

该操作沿用当前“打开记一笔支出”行为；不把未关联成本强行归属给任意供应商。

## 三、响应式布局

| 宽度 | 页面编排 | 关键限制 |
|---|---|---|
| 375–430px | 单列：结论 → 饼图 → 变化三行 → 风险摘要 → 供应商 | 每行保留 44px 最小点击高度；金额、占比、变化值不换行；“其他/全部”收纳低优先级分类。 |
| 768–1023px | 两列首屏：左侧结论 + 饼图，右侧变化前三项；下方风险与供应商并列 | 两列只改变空间编排，不改变阅读顺序和所有下钻目标。 |
| ≥1024px | 结论与结构在第一行；变化对比横向扩展成严格财务列；风险与供应商作为第二行 | 不拉大字体；使用对齐、表格列和留白提升密度。 |

所有尺寸都沿用现有冷白背景、深海军蓝正文、品牌蓝当前值、橙色上期、绿色改善和红色风险的语义体系。模块之间使用 12–14px 间距、16px 圆角与细实线分隔，不恢复厚阴影、装饰网格或大屏式图例。

## 四、交互与状态规格

| 状态 | 结论卡 | 结构区 | 变化区 | 供应商区 |
|---|---|---|---|---|
| 有完整数据 | 金额 + 环比 + 最大原因 | 前 3 + 其他 N 类 | 变化前三 + 全部 | 前三排行 |
| 无成本 | 补录成本行动 | 简短空态 | 不展示 | 单行引导关联支出 |
| 无上期 | 金额 + “暂无上期基线” | 正常展示 | 上期零柱、无伪造变化 | 当前期间真实排行 |
| 有回冲 | 增加正向−回冲=净成本等式 | 饼图中心为正向成本 | 正常展示 | 正常展示 |
| 无关联供应商 | 正常 | 正常 | 正常 | 一行空态行动 |
| 减少动态效果 | 所有数值立即稳定 | 禁用饼图/柱体进入动画 | 禁用柱体进入动画 | 禁用排行入场动画 |

## 五、实现边界与组件拆分

推荐在不更改数据层的前提下新增或重组以下展示组件。

| 展示组件 | 输入 | 不可改变的契约 |
|---|---|---|
| `CostDecisionCard` | 现有 `costSummary`、`structure[0]`、期间切换回调 | 净成本、回冲和环比计算保持原值；最大分类按原排序。 |
| `CostCompositionPreview` | `costSummary.structure`、`grossCost` | 饼图只使用正向成本；其他分类只作当前项聚合，不伪造分类。 |
| `CostChangePreview` | `structureComparison` | 本期/上期各自占比与 `shareDelta` 不变；零基线可见。 |
| `RiskReviewDisclosure` | 现有利润桥、趋势、隐形成本及摘要状态 | 无新增预测或新的风险分数。 |
| `SupplierAttribution` | `supplierRankings` | 仅展示已关联、已入账的真实支出。 |

在完成上述组件重排后，再清理 `AnalysisPageContent` 和 `AnalysisPage` 中首个 `return` 之后的不可达历史 JSX。清理必须最后进行，并由现有结构、供应商、空态和下钻 DOM 回归保护。[1]

## 六、实施顺序与验收标准

### 实施顺序

| 阶段 | 范围 | 风险控制 |
|---|---|---|
| P0-A | 重做结论卡，将最大原因与下钻行动并入首屏 | 不触及 `buildCostAnalysisSummary`；对回冲、无上期、无成本分别断言。 |
| P0-B | 将结构对比收束为变化前三财务列 + 查看全部 | 保持 `buildCostStructureComparison` 排序、零柱和下钻。 |
| P1 | 饼图前 3/其他 N 类、风险摘要、供应商单行空态 | 不引入数据估算；无关联供应商持续为空态。 |
| P2 | 768px+ 网格布局、不可达 JSX 清理、动效收口 | 先补 DOM 与宽屏截图，再删除历史展示分支。 |

### 验收标准

| 维度 | 验收条件 |
|---|---|
| 3 秒理解 | 用户无需滚动即可读到净成本、最大分类和一个下钻动作。 |
| 数据一致性 | 饼图正向成本、结论净成本、回冲等式、分组柱的本期/上期占比与当前测试夹具完全一致。 |
| 真实空态 | 无上期、无成本、无供应商关联不显示虚假的变化、排行或预测。 |
| 操作可达 | 首卡最大原因、饼图图例、变化行、供应商行均能进入正确期间/分类/供应商流水。 |
| 设备适配 | 375px、390px、430px、768px、1280px 下没有横向溢出；字体、金额列和触控区保持可读。 |
| 视觉稳定 | 切换期间与展开风险详情不会触发趋势图闪烁；`prefers-reduced-motion` 下无非必要图表动效。 |
