# 算得清首页显示效果审计

**审计日期：** 2026-08-21  
**审计范围：** 首页“经营”Tab 的默认真实账本状态。当前状态为：电商行业、本月净营收为零、有成本分录、未设置销售目标、未录入带 SKU 的订单。  
**视口证据：** 375 × 812、390 × 844、430 × 932；另核对 375px 首屏的底部导航。

> 本次为**显示效果与信息架构审计**，不对账本计算结果本身下结论。需要特别处理的是：同一“本月成本”在核心结果与成本结构模块中出现可见差异，已按 P0 视觉可信度问题提出核对要求。

## 结论摘要

首页已具备明确的产品识别：Digital Blue 主结果卡、账本格线、行业标签、成本结构与五级底部导航在三档宽度中没有溢出或遮挡。首要问题不是“页面不好看”，而是**数据可信度、行动优先级与空状态信息效率**尚未收口。核心结果卡显示本月成本 **¥115,680**，成本结构环却显示约 **¥105,000**；若不解释收口范围，会直接损害经营账本的可信度。其次，未设目标与无 SKU 订单的两张状态卡说明偏多、主行动偏弱，用户无法在一眼内知道“先做哪一步”。

| 维度 | 结论 | 风险等级 |
|---|---|---|
| 数据一致性 | 核心成本与成本结构的可见金额不同，缺少范围说明 | P0 |
| 首屏行动优先级 | 当前有三种风险/待补数，但缺少唯一主行动 | P1 |
| 空状态效率 | 销售目标和商品动能卡使用居中说明，数字和行动关系不够直接 | P1 |
| 顶部身份与提醒 | 品牌区与提醒均过小，紧急经营信号辨识弱 | P1 |
| 账本蓝图一致性 | 主卡强、白色模块偏通用圆角卡，账本规则未贯穿 | P2 |
| 促销模块克制性 | Banner 在默认无订单状态下仍占一段视觉面积 | P2 |

## 推荐修正顺序

1. **先处理 P0 成本口径显示。** 修正或标注“总成本/已分类成本/未分类调整项”的关系，再进行任何视觉微调。
2. **收束默认空状态为一个主行动。** 当前状态应优先驱动“查看预算预测”，并在随后两个次级位置提供“设置目标”“录第一笔 SKU 订单”。
3. **重构三张白色模块的账本行。** 目标、动能、成本结构分别按“结果 → 缺口/原因 → 下一步”排列，避免中心化大段解释。
4. **提升顶栏与行业模板识别。** 扩大风险提醒可点击区，强化“店铺印章 + 算式 + 算得清字标 + 签名线”，并将电商风险语言统一到首页各处。
5. **最后收束 Banner。** 让其只承担产品宣传；在经营缺口明显时降级或替换为与当前行动一致的短提示。

## 审计限制

本轮只审计了当前真实本地账本状态：**未设置销售目标、未录入带 SKU 订单、存在成本和预算风险**。因此“已设目标完成环”和“有订单后的销售/商品排行”没有在本轮截图中出现。建议完成 P0 与 P1 修正后，分别使用“已设目标且落后”“有订单且有 SKU”“多分类成本”三种真实数据状态再做一次状态覆盖审计。
