# 算得清移动端 UI 最高标准检查记录

## 检查基线

本轮以 390×844 移动端视口为首要检查尺寸，并以移动端财务工具的可读性、单手可操作性、跨页一致性、色彩对比、关键状态反馈和行业识别为验收尺度。首屏已验证为“行业—本月成本—预算—优先风险”的顺序，深色总览卡与底部导航在小屏下没有出现截断或重叠。

| P0 | 财务数字层级 | 关键金额已使用等宽字体，部分列表的列对齐需要持续核查 | 金额、百分比、排名使用等宽并按数据列右对齐 |

| P1 | 触控与反馈 | 主入口与固定操作键需逐页复核 | 可点击元素不低于 44px，保存/删除提供明确反馈 |

## 逐页检查发现与修复

在 390px 与 375px 宽度下复核了工作台、记账、分析、我的、行业切换、成本卡、订单、预算、SKU、成本报表、供应商、分类及其主要新增表单。未发现内容横向溢出、底部导航覆盖内容或二级页面缺少返回入口。检查中发现订单录入页的渠道费用模板因布局规则导致文字断裂，已改为完整的纵向信息块；同时将页头返回、详情动作和智能定价关键操作统一提升至更可靠的触控高度。

供应商与分类的删除图标仍需要在下一步检查中确认最终命中面积；其视觉呈现已保持了危险操作的低干扰表达，后续将继续避免在密集列表中引入误触风险。

## 修复后复核

在 375×812 视口复核订单录入、记一笔与预算管理页面。渠道默认费用模板现已完整显示为“标题—费用口径—说明”的纵向结构，不再出现文本与图标分离；页头返回按键已扩大；记录保存、订单入账、预算保存均保留了清晰的固定主操作区。表单内容在键盘前的自然滚动区域内完整可见，未与底部操作重叠。

在 390×844 视口进行最终复核时，工作台、记账、分析、订单录入及分类管理均维持了统一的冷白底、深海军蓝总览、蓝色账本页签、等宽财务数字与底部安全间距。分类与供应商列表的删除控件已扩大为 44px 命中面积，密集列表仍能保持金额列和危险操作的清晰分离。

## 质量门禁

类型检查通过；4 组自动化测试、共 17 项用例通过；生产构建通过。构建工具仅报告现有前端主包超过默认体积建议值，未阻断发布，也不影响本轮界面检查结论。后续若继续扩展产品，可按业务页面拆分代码包以缩短首次加载时间。

### 本轮专业优化

在真实 390px 视口中，成本卡与订单账本的新增操作原本位于内容流末尾，短列表时视觉位置偏上，长列表时又可能被滚动带离拇指区。现已作为常驻底部主操作处理。工作台趋势卡同步由泛化的“经营趋势”改为“真实成本趋势”，以本月成本、成本柱形与环比判断组成统一的财务叙事，避免成本图形与毛利率文案的口径混淆。

复杂表单复审还发现两项小屏风险：竞品与促销模拟继承了详情容器的横向布局，导致第三个输入字段在窄屏受挤压；成本项行的编辑与删除图标在 44px 触控规则下共享了不足的列宽。现已将模拟字段明确恢复为两列网格，并为成本项动作栏分配两个独立的 44px 命中区。

在信息密集的账本列表中，非激活导航与说明文字原先使用了偏浅的灰度，不利于快速扫读。当前将这些辅助文字统一收束到更高对比的中性灰，同时保持关键金额、风险与主操作仍由深海军蓝、数字蓝和状态色承担层级。

### 最终设计复核

最终在 390×844 视口复核了工作台、账本、分析、成本详情与智能定价。页面现已稳定形成“深海军蓝经营总览—蓝图刻度白色账页—等宽财务数列—可行动判断”的连续体验。成本详情的编辑、智能定价、删除三种动作具备明确层级；定价页的保本、建议价、竞品/促销模拟与价格档位依次展开，保持了从成本到决策的阅读路径。

本轮没有发现横向滚动、固定操作覆盖表单内容、未恢复的返回路径或客户端运行时错误。类型检查、17 项自动化测试和生产构建均通过；构建仍保留现有主包体积提示，属于后续性能优化事项，不影响本轮 UI 质量验收。

## 证据

首页截图检查显示：品牌头部、深海军蓝成本总览、预算/毛利数据列、风险提示、快捷经营入口、分类明细、趋势卡和固定底部 Tab 均在 390px 宽度内保持了完整可见的纵向秩序。后续检查将覆盖账本、分析、个人中心及各二级表单和详情页面，并对发现问题进行一次整体式修复。
