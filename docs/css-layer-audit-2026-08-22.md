# 历史 CSS 分层审计基线

当前前端样式由 `client/src/index.css` 与 `client/src/cashflow-filter.css` 共同承载，前者含全局、登录、资料、一级与二级页面的长期迭代规则，后者承载现行首页的高优先级布局。两份文件合计约 249KB、1,000 个物理行；由于单行聚合书写，仍存在同一选择器在不同阶段被重复声明的情况。

| 项目 | 当前基线 | 清理决策 |
| --- | ---: | --- |
| `index.css` | 约 187KB / 391 行 | 保留全局令牌、登录、资料、一级和二级页面的有效规则；优先拆除早期纹理与装饰层。 |
| `cashflow-filter.css` | 约 62KB / 609 行 | 作为现行首页布局源，清理前须以首页390px复核为前提。 |
| `background-size` 声明 | 23 | 逐一确认是否为图表坐标背景；页面卡片纹理应移除。 |
| 虚线声明 | 43 | 仅图表数据语义可保留，页面分隔和按钮装饰统一为细实线。 |
| 重复线性渐变装饰 | 19 | 不作为页面背景或卡片顶部装饰使用。 |
| 伪元素声明 | 171 | 保留图标、状态和图表所需伪元素；清理纯装饰线条。 |

候选审查组包括已经没有 `Home.tsx` 文字引用的早期摘要/快捷入口组件、旧版趋势与分析组件，以及资料媒体组件。该候选列表**不是直接删除清单**：动态类名、深层组件、认证入口和资料上传组件仍可能在运行时使用，必须先通过页面渲染和源码引用复核。

## 当前关键类名对照表

| 运行时页面/模块 | `Home.tsx` 根类或关键类 | 主定义文件 | 当前状态 | 处理顺序 |
| --- | --- | --- | --- | --- |
| 应用外壳与导航 | `mobile-shell`、`app-frame`、`page-header`、`tabbar` | `index.css`；少量响应式补充在 `cashflow-filter.css` | 多阶段重复声明，最终以全局后段与首页响应式规则共同生效。 | 将外壳、标题栏和导航令牌提取为唯一全局来源。 |
| 首页 | `prototype-home`、`home-redesign`、`home-decision`、`home-promotion` | `cashflow-filter.css` 为当前布局主来源，`index.css` 留有早期原型声明。 | 存在旧原型与后置首页重构两层。 | 先保留当前有效布局，逐步删除被 `home-redesign` 覆盖的旧原型声明。 |
| 订单 | `prototype-orders`、`ledger-page-shell`、`ledger-row-list` | `cashflow-filter.css` | 一级页面白底列表已稳定；全局层仍提供通用行组件补充。 | 收敛为统一列表承载面和细实线规则。 |
| 商品 | `prototype-products`、`product-cost-list`、`ledger-data-columns` | `cashflow-filter.css` | 列表、SKU 指标与微趋势均为当前运行时模块。 | 保留数据密度结构，只合并重复颜色/圆角声明。 |
| 分析 | `prototype-analysis`、`analysis-*`、`ledger-surface` | `cashflow-filter.css`；基础图表规则在 `index.css` | 图表模块有跨文件继承，部分基础规则仅提供数据图形语义。 | 仅移除页面纹理和装饰线，不删图表坐标与数据状态。 |
| 个人中心 | `prototype-profile`、`profile-*` | `cashflow-filter.css` 与 `index.css` | 资料、头像和店铺品牌组件仍为动态业务路径。 | 不纳入自动删除；后续只统一卡片令牌。 |
| 资料异常态 | `profile-load-state`、`empty-state-actions` | `index.css` | 单一、已复核的异常恢复样式。 | 作为异常态基准保留。 |

对照结果表明，当前主要风险不是某一页面缺少样式，而是外壳、首页和通用列表规则在两份样式表中多次声明。自动清理只处理没有任何 TypeScript/TSX 引用的整组组件；仍在运行时使用的关键类保持人工迁移和截图复核流程。

## 三类规则处理清单

| 类型 | 代表规则组 | 证据 | 当前处理状态 |
| --- | --- | --- | --- |
| 已确认失效 | `summary-*`、`quick-grid`、`category-card`、`risk-card`、旧 `mini-trend-card`、`analysis-hero`、`metric-strip`、`home-cost-trend`、`home-data-row` | 在前端 TypeScript/TSX 源码中未发现类名引用，且390px首页、订单、商品、分析、我的与资料异常态截图无布局回归。 | 已从 `index.css` 删除其完整选择器规则。 |
| 重复定义 | `mobile-shell`、`app-frame`、`page-header`、`tabbar`、`ledger-surface`、`ledger-row-list` | 同一类在全局层、原型层或首页筛选层多次声明。 | 保留运行时有效定义；下一批按“全局令牌 → 页面布局 → 局部组件”迁移，避免一次性改动导航和列表。 |
| 仅靠后置覆盖 | `prototype-home` 的早期声明与 `home-redesign`、`cashflow-filter.css` 的首页最终布局 | 当前首页由后段首页重构规则实现；早期原型规则不再是视觉事实来源。 | 先锁定截图基线，再将有效值回写到主声明并删去被遮蔽的早期规则。 |

本表将“安全自动删除”和“必须人工迁移”分开处理：前者已完成且可重复运行审查脚本；后者须在每一次合并后通过关键页面截图与功能回归验证。

本轮清理的原则如下：页面底板使用冷白与轻微层次，内容承载面使用白底、细实线和克制阴影；金融数字继续使用 `--financial-numeric-font`；数据图表内部坐标线可保留，但不将其扩展为页面纹理；所有删除或合并均不得改变页面层级、URL、表单和数据逻辑。

## 第一批已处理规则

通过对 `Home.tsx` 及整个前端 TypeScript/TSX 源码的类名引用核验，确认摘要卡、旧快捷入口、早期分类卡、旧风险卡、旧趋势/分析组件及若干原型兼容组件未被当前运行时引用。审查脚本以“整条规则的每个选择器都属于未引用组件”为删除门槛，首批安全删除 211 条规则，`index.css` 从约 187KB 收敛至约 166KB；生产 CSS 压缩输出从约 215KB 降至约 196KB。

删除后已重新通过首页、订单、商品、分析、我的和资料错误态的390px截图复核，以及 TypeScript、25 个测试文件共 91 项测试和生产构建。动态类名、认证入口、资料上传、图表和当前首页布局未列入自动删除范围，仍保留人工复核。

## 第二批视觉令牌收口

第二批在真实声明层完成 39 处页面虚线与非图表重复纹理归一化，并补充处理 23 处独立 `border-style` 与单轴网格背景声明。页面、空态、列表、消息、资料、预算、定价和首页承载面均改为无纹理/细实线；仅保留数据图形自身的坐标表达。样式表不再包含 `dashed` 声明，重复线性渐变仅留在图表数据表达中。

所有两份样式表中的旧 `IBM Plex Mono` 或 `MiSans` 字体族声明均已迁移为 `var(--financial-numeric-font)`，共更新 133 处声明。这样首页、订单、商品、分析、资料金额、趋势标签和表单数值都由用户确认的 A 方案统一控制：IBM Plex Mono 用于金融数字，Noto Sans SC 用于中文与令牌回退。

一级页面以 `--app-surface`、`--app-line`、`--app-radius`、`--app-ink`、`--app-muted` 和 `--financial-numeric-font` 为公共视觉令牌；订单、商品、分析仍以 `ledger-*` 变量补充其数据列表布局。390px截图复核确认首页、订单、商品、分析、我的及资料异常态均维持一致的冷白底、白色承载面、细实线、克制阴影、标题层级和数字可读性。第二批构建输出 CSS 约 194KB，较审计前的约 215KB 压缩输出继续收敛。
