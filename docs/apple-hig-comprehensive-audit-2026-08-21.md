# 算得清 · Apple HIG 全面设计审计

**审计日期：**2026-08-21  
**审计对象：**算得清 · 商家成本管家移动 Web App  
**审计方法：**以 Apple 官方 Human Interface Guidelines（HIG）为原则基线，结合 375px 与 390px 全页截图、首页有订单截图、当前页面结构和交互语义进行专家审查。该报告不是将产品机械改造成 iOS 原生 App，而是用 HIG 检验其**清晰、克制、可达、可信与一致**的经营体验。

> **总体结论：**当前版本已经具备鲜明的“账本蓝图”品牌和较清晰的五 Tab 信息架构，首页的“结果 → 缺口 → 成本结构”主线也基本成立。主要短板不在视觉方向，而在**无障碍基线、触控目标、跨页导航一致性及数据密集页面的渐进披露**。如果按 HIG 的生产级标准审视，建议先处理 P0 的可读性和可点性，再收束分析页和订单页的层级。

## 1. 审计框架与结论摘要

Apple 强调设计应聚焦目的、让用户保持掌控、使用熟悉且一致的模式、适配不同语境，并通过简洁和精细的细节建立信任。[1] 当前 App 对“经营数据优先”已有较好落实，但部分辅助文字与微控件为压缩密度牺牲了清晰度，和经营财务工具所需的可靠感不完全一致。

| 维度 | 当前评级 | 观察结论 | HIG 对应原则 |
| --- | --- | --- | --- |
| 任务聚焦与首页层级 | 良好 | 首页经营亏损、销售基线、成本结构的阅读顺序明确；宣传位位置已较克制。 | Purpose、Simplicity [1] |
| 视觉一致性 | 中等偏好 | 蓝图网格、数字列和分隔线逐渐统一，但一级页首、深色品牌带与卡片层级仍有多套语法。 | Familiarity、Craft [1] |
| 导航与信息架构 | 良好 | 五个顶级 Tab 清晰、均保留标签和稳定位置；符合顶级区域切换用途。 | Tab bars [6] |

## 2. 已符合或接近 HIG 的部分

### 2.1 首页的经营阅读路径已经以内容为主

首页在 375px 和 390px 均将“经营亏损 / 净营收 / 本月成本 / 月末预计超预算”置于首要视觉区域，随后呈现销售基线与成本结构。这符合将最重要内容放在阅读起点、通过空间和顺序建立层级的布局原则。[2] 产品宣传 Banner 位于成本结构之后，未夺取经营结果的主导权，方向正确。

### 2.2 顶层导航结构合理且稳定

“经营、订单、商品、分析、我的”是五个互斥的顶级区域，均保留图标与单字标签，并在空内容状态下仍保持可见。该结构符合 Tab bar 用于顶级导航、应保持稳定、应保留标签且避免溢出 Tab 的原则。[6] 当前不建议继续增加第六个 Tab；新增能力应落在现有页面或二级页。

### 2.3 空状态多数具备下一步行动

订单页“还没有订单”提供“记录第一笔订单”；首页销售基线提示“记录第一笔 SKU 订单”；分析页的利润瀑布和成本堆积均说明缺少的账本数据。此做法使用户能理解状态并恢复任务，符合 HIG 所强调的反馈、掌控和可恢复性。[1]

### 2.4 图表动效边界基本正确

柱、线、环和雷达图的动效被限制在进入和数据更新阶段，且实现了 `prefers-reduced-motion` 回退。Apple 明确要求动效应服务状态、反馈和说明，不应压过内容，也不应成为传递关键信息的唯一方式。[4] 当前方向符合，但仍需在真实设备上验证筛选连续切换时不会造成重复注意力负担。

## 3. P0：应优先处理的风险

### P0-1：辅助文字与财务图例过小，关键解释依赖 8–10px 字号

**证据。**首页销售基线说明、成本环中心的“分类已核对”、成本分类行、分析页图例、现金流说明、健康度维度公式、订单页空状态辅助说明，以及个人中心的资金公式均出现极小的辅助字。分析页尤其将“仅统计已标记现金方向的分录，不等同于利润”等口径放在小字号中。

**为什么重要。**Apple 对 iOS/iPadOS 给出的默认与最小自定义文字参考分别为 17pt 与 11pt；同时要求自定义字体与系统字体一样可扩展，并在较大字体时保持可读且尽量避免截断。[3] [5] 在财务产品里，口径、状态和金额解释不是装饰性副本，过小会降低核对和信任。

**修正方案。**将所有会影响理解、风险判断或点击决策的文本分为三层：正文/指标标签不低于 13–14px，状态和图例不低于 11–12px，纯装饰刻度可保留 10px。为 `html` 设定可缩放的根字号或提供“显示密度”选项；针对 120%–200% 文字放大，将三列金额改为可堆叠两行布局，而不是继续 `nowrap` 截断。健康度公式与现金口径需可展开阅读，不应只依赖 9px 固定文案。

### P0-2：部分微控件的可点击面积不足，尤其是轮播圆点和紧凑筛选

**证据。**宣传 Banner 的单个圆点视觉尺寸约 5px；轮播暂停控件和若干筛选 Chip 的可见尺寸也显著小于主按钮。分析页现金流渠道/供应商筛选在数据较多时需要横向滚动，且单个 Chip 偏小。

**为什么重要。**Apple 建议 iOS/iPadOS 默认控制尺寸为 44×44pt，最低为 28×28pt，同时强调控制之间需要足够间距以降低误触。[3] 视觉图标可以小，但命中区域不能随之缩小。

**修正方案。**保持圆点视觉尺寸不变，但让每个轮播页码按钮的透明命中区至少 32×32px，并将暂停控件和相邻圆点分离为 44px 高的操作带。筛选 Chip 设置最小高度 36–40px，横向滚动时提供明确的边缘渐隐或“更多筛选”入口。所有图表下钻按钮、图例筛选和小箭头均应通过父容器扩大命中区，而不是只放大图标。

### P0-3：尚未建立可验证的动态字体、对比度与辅助技术验收

**证据。**当前已完成 375/390/430px 截图验收，但证据范围未包含 iOS Larger Text、Increase Contrast、VoiceOver、Full Keyboard Access 或真实安全区。页面大量使用固定像素字、固定高度行和 `white-space: nowrap`。

**为什么重要。**Apple 要求布局适应文字放大、不同设备和安全区域；同时建议自定义颜色达到适当对比度，且不应只用颜色表达状态。[2] [3] 目前颜色之外的图标/文字提示通常存在，这是优点；但没有自动化或设备级验收，仍不能证明合规。

**修正方案。**新增无障碍验收矩阵：100%、125%、150%、200% 文字缩放；浅色/高对比度；375×667、390×844、430×932；TalkBack/VoiceOver 朗读顺序；键盘焦点顺序。用自动对比度检查器验证浅蓝文字、灰色月份、细小图例和禁用态，不通过 4.5:1 的小字在默认主题下需加深或提高字号。[3]

## 4. P1：显著改善体验和平台感的问题

### P1-1：五个一级页面的页首语法不一致，削弱熟悉性

首页使用 Logo + 滚动风险线；订单页切换为深海军蓝品牌带；商品页使用白底页首 + 新增按钮；分析页为纯标题；个人中心为店铺资料卡。品牌并非不能变化，但当前变化更多来自历史模块叠加，而不是页面目的的清晰区分。

Apple 强调一旦建立元素的外观或行为，就应在设计中一致使用，以帮助用户快速学习和建立信心。[1] 建议制定三级页首：**顶级经营页**使用轻品牌栏与风险入口；**列表页**使用标题 + 搜索/新增工具栏；**设置页**使用简洁返回栏 + 页面标题。订单页的深色带应仅保留为“订单工作区”有明确语义的例外，或改为同样的轻品牌栏。

### P1-2：分析页的“解释、图表、提醒、公式”在同屏并列，渐进披露不足

分析页的健康度卡在一个模块中承载评分、五个维度、原始公式、缺口和跳转；现金流卡同时包含图例、筛选、柱形、说明与下钻。内容本身合理，但在 375px 时阅读负荷较高。

HIG 建议用渐进披露帮助人们发现当前隐藏内容，并为核心信息留出足够空间。[2] 建议将健康度卡首屏收束为“总分/待补数 + 最高风险 + 查看五维”；将维度公式移入底部 Sheet 或专页。现金流将筛选收进“筛选”按钮和可展开区，默认只显示当前口径。这样能让“结果 → 原因 → 行动”更清楚。

### P1-3：空状态的视觉重量有时接近正常业务模块

分析页“近 6 月成本结构”在不足两个月时显示带边框的较大说明框；订单页空状态则使用图标、公式及主按钮。两者都可行动，但视觉处理不一致：前者像异常表单，后者像引导页。

建议建立三种状态模板：**无数据**（图标 + 一句原因 + 一个行动）、**数据不足**（保留灰化坐标基线 + 一句缺口 + 一个行动）、**风险异常**（金额/状态 + 风险原因 + 一个行动）。不要用深色边框模拟警告，除非该状态真的需要立即处理。

### P1-4：底部 Tab 符合结构，但仍需更接近安全区与系统层的表现

五 Tab 数量和标签均合格；但当前 Web App 的白色固定栏在浏览器环境里容易与系统浏览器底栏、设备手势区叠加。Apple 指出 Tab bar 等控制层会浮于内容之上，布局需要考虑安全区。[2] [6]

建议为固定 Tab 使用 `padding-bottom: env(safe-area-inset-bottom)`，并让滚动内容的底部 padding 按实际 Tab 高度 + 安全区计算。视觉上可使用更弱的上边界与半透明背景/背景模糊，但不要为了模仿 Liquid Glass 而牺牲文字对比度。需要在 Safari PWA、iOS 浏览器和 Android 浏览器分别验证。

### P1-5：宣传轮播为定时变动内容，经营页面应默认更安静

自动轮播处在首页底部，影响较低，且已有暂停控件；但 HIG 建议避免对用户自动关闭或在时间轴上变化的内容造成不必要认知负担，并要求动效必须克制。[3] [4] 对经营数据 App，建议默认使用静态首张宣传卡，仅在用户横滑或点击页码时切换；若保留自动轮播，应提供显著的暂停与“减少动态效果”同步回退。

## 5. P2：提升精细度与 iOS 平台感的机会

| 编号 | 观察 | 建议 |
| --- | --- | --- |
| P2-1 | 主体中文字体、等宽金额字体和品牌字标混用较多，财务数字有效，但次级中文字体的细节略显密。 | 主文字优先使用系统字体栈，IBM Plex Mono 仅用于金额、日期、公式和编码。 |
| P2-2 | 多数白色模块同时使用圆角、网格和细阴影，页面在长列表时仍有轻微“卡片堆叠”感。 | 让连续列表更多使用分隔线和共享背景；保留圆角卡给关键结果、图表和行动组。 |
| P2-3 | 订单筛选“全部 / 低利润 / 退款”的默认选中态对比偏弱。 | 增加选中项的文字对比、填充或底部指示，不要只依赖极浅背景。 |
| P2-4 | 经营数据中蓝色同时表示主行动、普通趋势、选中态和部分正向信息。 | 建立语义色：蓝色为操作/中性趋势，绿或明确文案为达标，橙/红为风险；颜色之外持续保留文字和图标。 |
| P2-5 | 目前动效正确但覆盖面较广。 | 将首次加载卡片入场限制在首屏或首次访问，避免每次切 Tab 时所有图表再次依次出现。 |

## 6. 推荐修正顺序

| 批次 | 内容 | 成功判定 |
| --- | --- | --- |
| 第一批：可达性基线 | 最小文字、对比度、44px 命中区、动态字体/安全区验收。 | 关键说明不低于 11px 等效可读基线；所有微控件存在 ≥28px 命中区，主操作 ≥44px。 |
| 第二批：结构收束 | 统一一级页首、健康度/现金流渐进披露、状态模板。 | 用户可在 3 秒内识别页面目的、当前状态和下一步动作。 |
| 第三批：平台精细度 | Tab 安全区、筛选选中态、系统字体与语义色、动效触发频率。 | Safari PWA/浏览器下无底部遮挡；状态不单靠颜色；Tab 切换不产生过度动画。 |

## 7. 审计边界与后续验证

本次是对 Web App 的 HIG 对齐审计，不能替代原生 iOS 的 Accessibility Inspector、VoiceOver、Dynamic Type 和真实 Safari PWA 验证。结论中关于字号、命中区和对比度的 P0 项应在真实设备和系统辅助功能中复核。产品无需放弃“账本蓝图”的品牌风格；正确目标是让该风格在 Apple 所强调的清晰、熟悉、适配和精细约束内工作。
