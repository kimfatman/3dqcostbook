本批围绕首页的时间语义、月度待办、目标异常提示与成本卡历史成本可见性进行收口。改动仅涉及 `client/src/pages/Home.tsx`、后置视觉样式和真实 DOM 回归测试；未修改账本指标内核、订单写入、退款写入、金额存储或后端数据模型。

| 整改主题 | 已实施行为 | 明确未改变的边界 |
| --- | --- | --- |
| 首页时间范围 | 经营主卡继续默认“今天”，可切换今天、本周、本月；主卡、订单数、客单价、退款影响均按所选范围展示。 | 月预算、本月销售目标、近 7 日订单趋势、最新流水不被伪装成“今天”数据。 |
| 共享待办 | `notificationItems` 保持为唯一的月度待办聚合；首页主卡和“我的”均从 `homeDecision.priority` 读取最高优先项。 | 不新增第二个“优先处理”列表，不改变预算、成本卡、低利润订单或退款的排序规则与下钻目标。 |
| 周期和单位 | 首页以“本月待办”“本月经营提醒”“本月销售目标”“近 7 日”明确不同时段；销售动能标题由真实标签显示一次“近 7 日”。 | 金额继续使用人民币两位小数显示；比率使用 `%`；订单数使用“笔”；SKU 销量使用 SKU 自身单位。 |
| 目标异常 | 当真实 `completionRate > 120` 时显示“本月目标可能偏低”，并提供“复核目标”进入既有编辑入口。 | 不自动上调目标，不修改销售额、完成率、月末预测或归档。 |
| 成本快照 | 成本卡详情读取关联 SKU 的最近订单行 `unitCostFen`，并与当前 SKU 单位成本并列、只读展示。 | 历史订单价格与成本快照不被写回；没有历史订单时展示真实缺口，不用当前成本伪造历史成本。 |

## 历史成本快照读取规则

> 最近成交冻结成本仅从订单行 `OrderLine.unitCostFen` 读取。订单按 `occurredAt`、`createdAt` 倒序选取最近一行；关联条件为当前成本卡所对应的 SKU `id`。

因此，成本卡、BOM、间接成本分摊或 SKU 当前单位成本的后续编辑，只会影响以后创建订单时冻结的成本，不会重算既有订单的已售成本。
