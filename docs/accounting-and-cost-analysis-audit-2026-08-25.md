# 核算与成本分析审计记录

**审计日期：** 2026-08-25  
**范围：** 当前客户端账本内核、订单与退款、成本卡/BOM、间接成本池、预算、智能定价，以及成本分析与首页图表的数据口径。服务端未发现重复的金额汇总或利润计算实现；本次结论以客户端统一账本模型为准。

> **结论：** 收入、退款、销售成本、经营费用、毛利和经营利润的核心账本关系保持可复算。本次审计修复了未分类成本在分析中被漏看的风险、实际间接成本可能再次进入后续订单已售成本的重复扣减风险、隐形成本估算的整元取整偏差，以及浮点半分边界的最小货币单位转换问题。成本分析首屏现以“净成本 + 正向成本结构 + 成本回冲”的方式解释数据边界。

## 1. 核算不变量

| 项目 | 统一口径 | 审计结果 |
|---|---|---|
| 净营收 | 销售收入 + 其他收入 − 客户退款 | 通过；仅已入账分录参与汇总。 |
| 毛利 | 净营收 − 销售成本 | 通过；退款主分录不混入销售成本。 |
| 经营利润 | 毛利 − 经营费用 | 通过；经营费用与销售成本独立归类。 |
| 现金流 | 仅按现金流入/流出方向汇总 | 通过；已明确不等同于利润。 |
| 预算占用 | 用户选择“经营成本”或“现金流出”作为基数 | 通过；超支不封顶，保留真实超额比例。 |
| 金额精度 | 最小单位为分；展示保留两位小数 | 已修复浮点半分边界，`1.005` 与 `-1.005` 分别稳定转换为 `101` 分和 `-101` 分。 |

## 2. 订单、退款与项目成本

订单创建时冻结成交价和**直接已售成本**，退款在退款发生期冲减净营收；只有“可售回收入库”才冲回已售成本。退款手续费作为经营费用保留，渠道佣金和履约费用在订单售后利润中属于渠道模板的**估算值**，不会冒充已入账经营费用。

间接成本池按销量、营业额、项目数或人工比例分配到项目完全成本。审计后，已发生的实际间接成本只会在正式账本中进入一次经营费用；项目分摊仅服务成本卡和智能定价，不再写入新订单的已售成本。退款会从当期分摊动因中扣回数量和退款额，避免对当期退回的成交额继续分摊。

| 已修复问题 | 原风险 | 修复后边界 |
|---|---|---|
| 未配置分类成本 | 历史删除分类、退款手续费等可能不出现在分类结构与报表快照中 | 统一归入“未分类成本”，与利润表总成本保持可追溯。 |
| 实际间接成本分摊 | 实际费用已入账后，分摊额可能再次推高后续订单 COGS | SKU 分离直接成本和管理分摊；仅完全成本与定价使用后者。 |
| 隐形成本估算 | 行业基准估算按整元取整，与两位小数政策不一致 | 基准估算保留两位小数，且继续明确不计入正式利润。 |
| 成本回冲表达 | 可售回收入库会降低净成本，若直接混入结构会扭曲占比 | 净成本单独用于经营结果；结构只显示正向成本，成本回冲单独提示。 |

## 3. 成本分析的期间与展示口径

成本分析的“本月/上月”使用同一行业、同一自然月、已入账分录。首屏的总额来自销售成本与经营费用的净额；正向成本结构按正额成本计算占比，成本回冲不会被误读成某个成本类别的负占比。环比对比对缺失的上一期分类按零处理，优先处理项从全部正向成本分类中选择，而不是被前五展示项限制。

趋势图、成本堆积图和现金流图各自保留不同语义。近七日销售动能按成交日显示毛销售与订单数，不用售后日的退款改写成交日；净营收仍以账本核算为准。月度成本堆积只聚合已入账销售成本和经营费用；现金流只聚合已标记现金方向的分录，并在页面提示其不等同于利润。

## 4. 用户理解边界

成本分析首屏的阅读顺序是“已入账净成本 → 最需要处理的成本项 → 正向成本结构 → 按需展开趋势与风险复核”。行业隐形成本始终以“基准估算”显示，并给出计算基数、比例和核对动作；该金额不进入净营收、毛利、经营利润或预算实际占用。

以下两类数据仍需要商家补录，系统不会擅自把估算写成真实利润：其一，平台实际结算佣金、履约支出与订单模板估算之间的差异；其二，非 SKU 手工退款对应的退货回收成本。商家应在流水中记录实际费用，并在退款时选择可售回收状态，才能让经营利润与项目售后利润共同收敛。
