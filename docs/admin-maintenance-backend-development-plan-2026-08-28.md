# “算得清·商家成本管家”管理维护系统后端开发规划

**主办 Agent：**后端 Agent  
**任务分支：**`agent/backend/admin-maintenance-backend`  
**规划日期：**2026-08-28  
**规划目标：**为独立管理员前端提供一套完整、可审计、服务端强制授权的管理维护系统后端，不改变普通商家端的经营路径、账本口径或历史订单快照。

## 一、规划结论

当前项目已经具备 Express/tRPC 服务、Drizzle/MySQL 数据层、本地会话、`app_users.role` 管理员角色、工作区成员权限、账本快照、私有媒体和工作区审计基础。当前 `server/routers.ts` 只有认证、个人资料和工作区过程，没有独立的管理员路由；`server/db.ts` 也只支持按用户或工作区访问，缺少跨工作区的管理员只读查询、运营聚合、系统状态汇总和管理动作审计。因此本任务的首要后端缺口不是重建账本，而是建立一个与商家端隔离的 `admin` tRPC 路由域及其数据访问边界。

首版管理平台应以“**看清系统状态、定位问题、维护最小字段、保留完整审计**”为核心，而不是做成可直接改写商家账本的超级后台。所有管理过程必须在服务端经过 `adminProcedure` 授权；前端菜单隐藏、独立 URL 或路由守卫只能作为体验层，不得作为安全边界。

> 管理员后台只返回运营所需的最小字段。它不得返回密码哈希、验证码、CloudBase verification id、verification token、access token、会话签名、数据库连接信息、环境变量、COS 凭据或私有媒体原始内容。

## 二、当前实现基线

| 领域 | 当前已有能力 | 对管理平台的影响 |
|---|---|---|
| 身份 | `app_users` 使用本地会话；角色为 `admin` 或 `member`；`server/_core/trpc.ts` 已有 `adminProcedure` | 可直接复用服务端管理员强制鉴权，不新增前端可信角色字段 |
| 用户 | 邮箱、手机号、CloudBase subject、姓名、头像引用、创建/更新时间、最后登录 | 管理列表可展示脱敏联系方式、角色、验证状态和登录时间；敏感字段必须白名单返回 |
| 工作区 | 工作区资料、owner、行业、成员关系和更新时间 | 可建立用户—工作区运营视图，但不能越过工作区权限改写账本 |
| 账本 | `workspace_books.state` 为 JSON 快照，带 revision 和 schemaVersion；保存采用乐观锁 | 首版只做数据质量聚合与只读诊断，不在管理台直接修改账本 JSON |
| 审计 | `audit_events` 按工作区记录业务操作，含 actor、action、target 和 details | 需要新增全局管理员审计事件，避免把系统级操作伪装成某个工作区业务事件 |
| 健康 | `/healthz` 返回健康状态；系统路由有公开 health query | 管理台应新增管理员专用脱敏健康摘要，不能扩大公开健康接口的信息量 |
| CloudBase | 验证码挑战和第三方令牌只在服务端代理；浏览器仅接触 challenge id 和用户验证码 | 管理列表只能展示“已绑定/未绑定”等布尔状态，禁止显示 provider 标识或令牌 |
| 前端 | 现有商家端页面集中在 `client/src/pages/Home.tsx` 等文件，尚无专用 admin 页面 | 后端先提供稳定 tRPC 契约；管理员页面由专用 admin 前端实现，需 UI Agent 复核视觉、响应式和可用性 |

## 三、目标后端边界

管理平台采用独立路由域 `admin`，建议由以下模块组成：

| 模块 | 首版目标 | 首版不做 |
|---|---|---|
| 总览 | 服务健康、版本、数据库可用性摘要、最近任务结果、待处理风险数量 | 不显示服务器环境变量、连接串、密钥或完整错误堆栈 |
| 用户 | 分页搜索、角色、验证状态、最后登录、所属工作区数量、账户状态 | 不返回密码哈希、验证码、令牌；不默认展示完整手机号/邮箱 |
| 工作区 | 分页搜索、行业、owner 脱敏资料、成员数、账本更新时间、数据质量摘要 | 不在列表页返回完整账本内容或私有媒体 URL |
| 审计 | 管理员审计和指定工作区业务审计的只读查询、时间/动作/对象筛选 | 不允许普通店主查询全局审计；不把敏感输入写入 details |
| 数据质量 | 未分类流水、缺供应商、缺成本 SKU、异常 revision/schemaVersion 等聚合结果 | 不替商家自动修改数据；不直接重算历史订单或成本快照 |
| 版本与任务 | 应用版本、数据库迁移状态、最近受控任务执行结果、脱敏失败摘要 | 不由网页直接触发生产部署、不可逆迁移或任意 SQL |
| 维护动作 | 冻结/恢复账户、有限字段修正、配置草稿/发布（按授权逐步开放） | 首版禁止删除用户、删除工作区、批量改账本、重置密码、批量重算 |

## 四、建议 API 契约

所有过程均位于 `appRouter.admin` 下，并使用 `adminProcedure`。输入采用严格 Zod 白名单；分页、排序、筛选和搜索参数必须设置上限，避免管理台成为无界数据库查询入口。

### 4.1 只读总览

| 过程 | 输入 | 返回重点 |
|---|---|---|
| `admin.overview` | 时间窗口、可选工作区筛选 | `generatedAt`、应用版本、数据库健康、最近发布/任务状态、用户/工作区/审计计数、数据质量计数 |
| `admin.health` | 无 | `status`、检查时间、各依赖 `ok/failed`、脱敏错误摘要、耗时；不返回内部连接信息 |
| `admin.version` | 无 | 应用版本、构建时间、schema 版本、迁移状态、运行环境标签（非密钥） |

### 4.2 用户与工作区查询

| 过程 | 输入 | 返回重点 |
|---|---|---|
| `admin.users.list` | `page`、`pageSize`、关键词、角色、状态、验证状态、排序 | 用户最小资料、工作区数、最后登录和创建时间；邮箱/手机号默认脱敏 |
| `admin.users.get` | `userId` | 单用户运营摘要、工作区摘要、最近管理员相关审计；禁止返回密码哈希和令牌 |
| `admin.workspaces.list` | `page`、`pageSize`、关键词、行业、owner、数据质量状态 | 工作区最小资料、成员数、账本更新时间、质量计数 |
| `admin.workspaces.get` | `workspaceId` | 工作区摘要、成员最小资料、质量问题摘要、最近业务审计；不返回完整账本 JSON |
| `admin.workspaces.quality` | `workspaceId` 或批量工作区 ID，受限数量 | 聚合质量问题及可定位的对象 ID；不生成修复建议以外的隐式写操作 |

### 4.3 审计与任务查询

| 过程 | 输入 | 返回重点 |
|---|---|---|
| `admin.audit.list` | 时间范围、actor、action、targetType、结果、分页 | 管理员动作、目标、结果、时间、requestId、脱敏 details |
| `admin.workspaceAudit.list` | `workspaceId`、时间范围、分页 | 复用既有业务审计只读查询，但由管理员服务端授权并限制字段 |
| `admin.tasks.list` | 状态、类型、时间范围、分页 | 任务类型、状态、开始/完成时间、影响范围摘要、脱敏错误摘要 |

### 4.4 受控维护动作

| 过程 | 二次确认要求 | 服务端行为 |
|---|---|---|
| `admin.users.setStatus` | 输入 `confirm: true`、目标用户 ID、影响说明 token | 仅修改允许的账户状态；禁止自我降权；成功/失败/取消均写管理员审计 |
| `admin.users.setRole` | 输入 `confirm: true`、目标用户 ID、目标角色、影响说明 token | 仅允许授权角色转换；禁止移除最后一个管理员；记录旧值/新值的非敏感摘要 |
| `admin.config.saveDraft` | 输入配置版本与变更说明 | 只保存草稿，不影响线上读取；校验字段白名单和版本冲突 |
| `admin.config.publish` | 二次确认、版本号、影响说明 | 原子发布已审阅配置，写审计；禁止发布包含密钥、Token、验证码或原始业务数据的内容 |
| `admin.task.cancel` | 二次确认、任务 ID、影响说明 | 仅取消可取消任务；不可取消已完成或不可逆阶段；写入结果审计 |

**首版不提供删除、批量修复、工作区账本重写、历史成本重算、密码重置、生产迁移触发和部署触发过程。**若后续确需开放，必须先由统筹/发布 Agent 明确授权，并独立设计回滚、影响预览、幂等键和更高等级验证。

## 五、数据模型与迁移策略

本项目采用 schema-first。任何结构变化必须先修改 `drizzle/schema.ts`，再运行 `pnpm drizzle-kit generate`，审阅 SQL 后由有权限的发布流程执行迁移。规划阶段只定义迁移，不直接连接或修改生产数据库。

### 5.1 推荐新增表

| 表 | 主要字段 | 目的 |
|---|---|---|
| `admin_audit_events` | `id`、`actorUserId`、`action`、`targetType`、`targetId`、`requestId`、`outcome`、`details`、`createdAt` | 记录系统级管理员查询和维护动作；details 只能保存脱敏白名单 |
| `admin_tasks` | `id`、`type`、`status`、`requestedByUserId`、`scopeSummary`、`startedAt`、`finishedAt`、`errorSummary`、`createdAt` | 为健康页和任务页提供受控任务记录；不保存令牌、验证码和完整堆栈 |
| `admin_configs` | `id`、`key`、`version`、`status`、`payload`、`createdByUserId`、`publishedByUserId`、时间字段 | 支持配置草稿、发布和回滚；payload 需经过字段白名单校验 |

### 5.2 对现有表的最小扩展

`app_users` 若要支持账户冻结/恢复，需要新增受控的 `status` 枚举和必要的状态时间字段；默认值必须保持现有用户可用，历史数据只做非破坏性回填。若首版仅做只读管理台，可以将账户状态延后，避免为了展示而提前改变身份模型。

`admin_audit_events` 不应复用现有 `audit_events` 的必填 `workspaceId`，因为系统级动作可能没有单一工作区目标。现有工作区业务审计保持原有写入语义，以保证订单、账本和工作区历史不被改写。

### 5.3 迁移影响与回滚

新增表属于非破坏性迁移，历史用户、工作区、账本、订单、退款、SKU、成本卡和报表快照不受影响。新增可空或带安全默认值的账户状态字段属于非破坏性扩展。回滚方案是先停止使用对应新路由，再按发布流程回滚应用版本；数据库层仅在确认没有新表数据依赖后执行反向迁移。禁止直接删除现有列、重写 `workspace_books.state` 或修改订单历史快照。

## 六、权限与安全设计

管理员授权必须在每个过程的服务端完成。`adminProcedure` 当前依据 `ctx.user.role === "admin"` 强制拒绝未登录和非管理员请求；后续实现还需在测试中覆盖普通 member、未登录、管理员自我操作、最后管理员保护和越权工作区 ID。

敏感操作采用“**预览—确认—执行**”三步模型。前端先读取目标和影响范围摘要，服务端生成短时有效的一次性确认上下文；执行请求必须携带目标、版本/时间戳、确认标志和影响说明，服务端重新检查当前权限与目标状态，成功、失败和取消均写入管理员审计。确认信息不能只依赖前端布尔值。

系统状态响应只保留健康、版本、时间、任务状态、耗时和脱敏错误摘要。日志与审计 details 使用字段白名单和敏感词拒绝策略，确保 password、verification code、access token、authorization、cookie、secret、key、connection string 等内容不会写入日志或数据库。

所有列表过程都必须支持服务端分页并限制 `pageSize`；所有排序字段使用固定枚举；资源不存在与无权限访问要采用统一错误语义，避免普通用户通过响应差异探测管理员资源。管理端路由不得暴露给普通商家端导航，且即使用户手工输入路径或直接调用 tRPC 过程也必须得到服务端拒绝。

## 七、实施阶段

| 阶段 | 交付内容 | 主要文件范围 | 回归重点 |
|---:|---|---|---|
| P0 | 管理路由骨架、服务端 adminProcedure、健康/版本/概览只读接口 | `server/routers.ts`、`server/db.ts`、必要的 `server/admin/*` | 未登录、member、admin、脱敏响应、分页上限、数据库不可用 |
| P0 | 全局管理员审计表与写入 helper | `drizzle/schema.ts`、迁移、`server/db.ts` | 审计成功、失败、取消、敏感字段拒绝、历史业务审计不变 |
| P1 | 用户/工作区只读运营列表与详情、数据质量聚合 | `server/admin/*`、共享类型 | 越权 ID、最小字段、空结果、统计一致性、账本 JSON 不外泄 |
| P1 | 账户状态与角色受控维护 | schema、迁移、db、router | 二次确认取消、最后管理员保护、自我降权、失败回滚、审计完整 |
| P1 | 任务/版本/配置草稿与发布接口 | schema、迁移、db、router | 版本冲突、重复发布、失败不产生半状态、配置字段白名单 |
| P2 | 管理端前端适配与人工验收 | 专用 admin 目录或组件；由 UI Agent 复核 | 独立入口、响应式、键盘可达、错误/空态/确认弹窗 |
| P2 | 受控生产验收与交叉复核 | 不直接在本任务自行发布 | 统筹/发布 Agent 授权后验证健康、会话、媒体和账本链路 |

每个阶段遵循：`schema.ts → migration → db helper → admin router → Vitest → 前端适配 → 全量门禁`。路由文件过大时拆分为 `server/routers/admin.ts` 与 `server/admin/*`，保持单文件可审阅。

## 八、测试与验收标准

每项后端能力必须新增或更新 Vitest。至少覆盖以下边界：未登录请求返回未授权；普通 member 调用任何 admin 过程返回禁止且不泄露资源；管理员可读取最小字段；数据库失败返回稳定错误并不写入虚假成功审计；维护动作取消时数据与审计均不发生变更；成功和失败动作均留下 actor、action、target、outcome、时间和 requestId；不能删除或降权最后一个管理员；不能通过工作区 ID 读取未授权账本；响应和日志不含密码哈希、验证码、CloudBase token、数据库 URL 或私有媒体原始内容。

合并前必须运行并记录：

```text
pnpm check
pnpm test
pnpm build
```

涉及迁移时还要提交生成的 SQL 审阅记录、历史数据影响说明和回滚方案；迁移是否执行必须明确写为“未执行”或由统筹/发布 Agent 授权后的实际结果。涉及管理页面、表单、错误反馈或用户路径时，必须要求 UI Agent 复核视觉、响应式、键盘可达性和普通商家端隔离效果。涉及认证、迁移、部署或安全时，必须由统筹/发布 Agent 组织交叉复核。

## 九、前端适配契约

管理员前端只消费 `trpc.admin.*` 过程，不直接调用数据库、Express 内部对象或环境变量。页面建议拆为“管理总览、用户、工作区、审计、任务/版本、配置”六个独立页面，统一处理加载、空结果、失败和无权限状态。破坏性或高风险动作必须在 UI 中展示目标、选中数量、影响范围和取消入口，但服务端仍需重复校验。

前端不应依赖任何 CloudBase 浏览器 SDK，不应保存或展示 provider verification id、verification token、access token；管理台也不得通过 `VITE_CLOUDBASE_PUBLISHABLE_KEY` 绕过本站代理。管理员页面的标题、路由和导航必须与普通商家端分离，普通店主不得因接口名称、错误信息或隐藏链接发现管理操作。

## 十、风险与决策点

| 风险/决策 | 当前建议 |
|---|---|
| 是否首版支持冻结账户 | 建议先完成只读平台与审计，再引入 `app_users.status` 迁移和冻结语义 |
| 是否开放配置发布 | 首版只提供草稿和只读版本状态；发布需明确配置键、回滚和审批人 |
| 是否接入任务队列 | 首版仅记录受控任务状态；没有真实异步执行器前不伪造“已完成” |
| 是否直接管理账本 | 禁止直接编辑 `workspace_books.state`；数据质量只读并跳转商家端处理 |
| 是否公开健康信息 | 保留公开 `/healthz` 最小响应；详细健康只给管理员，且脱敏 |
| 是否生产迁移 | 本任务只生成并审阅迁移，不执行生产数据库操作；必须由统筹/发布 Agent 授权 |
| 管理前端实现 | 后端提供契约和安全回归；专用 admin 前端由 UI Agent 实现或复核，不重构普通商家端 |

## 十一、交接要求

实现完成后，PR 必须填写主办 Agent 的任务/会话标识、分支名、接口和迁移影响、管理员授权与审计边界、金额与账本不变量、失败/权限边界、测试命令与结果。交接给统筹/发布 Agent 时必须包含提交 SHA、迁移文件及是否执行、API 契约、已知风险、回滚方案、`pnpm check/test/build` 结果，以及需要 UI Agent 和用户验收的步骤。

当前规划阶段不提交生产发布、不修改生产数据库、不读取运行时密钥，不提交 `.env`、Token、验证码或用户生产数据。
