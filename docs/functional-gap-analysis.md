# 算得清：原始原型与当前移动 App 的功能差异审计

**审计范围：** 原始仓库 `cost-book-mini`（v2.4.1）与当前已发布的移动 App 重构版本。原始原型的功能基线来自其 README、API 契约和开发指南；当前版本以实际页面与已完成的手机端交互回归为准。

## 结论

当前版本的确存在明显的**业务功能回退**。移动端层级、底部导航和行业切换已经改善了使用结构，但迁移时只保留了“演示数据 + 页面外壳”，没有把原始原型中完整的业务模块一起迁入。当前版本应被视为一个可用的移动 App 壳层，而不是原有成本管理原型的等价替代。

> 原始原型覆盖记账、行业成本卡、分析、报表、供应商、分类管理等全链路；当前移动 App 只完整保留了行业切换和基础页面分级，记账、分析和成本详情均为简化展示版。

## 覆盖对照

| 原始模块 | 原始能力 | 当前状态 | 差异判断 |
|---|---|---|---|
| 工作台 | 店铺概览、KPI、预算、趋势、待办、快捷入口 | 保留行业、成本、预算、风险和快捷入口 | **弱化**：近 6 月趋势、待办联动与完整 KPI 未迁入 |
| 记账列表 | 按日分组、收入/支出切换、分类筛选、关键词筛选、浮动记账 | 按日分组和浮动记账可见 | **弱化**：筛选按钮未实现，缺少搜索、收入流水与实际新增列表项 |
| 记一笔 | 类型切换、金额校验、日期、分类、凭证面板、编辑复用 | 金额、行业分类、备注和成功提示 | **缺失**：类型、日期、商户、附件、编辑复用与完整保存对象均未迁入 |
| 行业成本卡 | 列表搜索/分类、成本详情、利润环、BOM 增删重算、单位成本趋势 | 按分类查看静态成本详情 | **核心缺失**：产品/菜品/服务项目列表、BOM、重算和趋势未迁入 |
| 成本分析 | 当期/上期构成、趋势、TOP5、供应商支出、隐性成本 | 预算进度与分类金额排行 | **弱化**：上期对比、图表、TOP5、供应商排行和隐性成本模型未迁入 |
| 成本报表 | 月报列表、报表详情、成本明细、毛利统计、导出 | 无对应页面 | **完全缺失** |
| 供应商 | 分组、搜索、新增、编辑、删除、电话动作 | 无对应页面 | **完全缺失** |
| 分类管理 | 新增、编辑、删除、颜色选择、占用校验 | 无对应页面 | **完全缺失** |
| 行业模板 | 五行业分类、配置和行业模型切换 | 五行业选择、店铺/分类/风险文案切换 | **弱化**：行业隐性成本计算与行业化成本实体未迁入 |
| 数据与接口层 | 16 个 API 桩、单一 DB、异步加载、聚合与重算边界 | 页面组件内静态数据与少量 React 状态 | **核心缺失**：没有统一数据层，保存记录不会新增流水，也没有复用原有 16 个业务契约 |

## 已确认的关键回退

| 优先级 | 回退点 | 对用户的直接影响 | 恢复原则 |
|---:|---|---|---|
| P0 | 记账没有真实记录生命周期 | 保存后只改变概览金额，不新增、编辑或删除流水 | 先恢复 `records` 数据集及列表回写，再做筛选和详情 |
| P0 | 行业成本卡与 BOM 缺失 | 产品/菜品/服务项目成本无法核算，产品核心价值丢失 | 复用原始产品、成本项、重算口径，按行业显示正确术语 |
| P0 | 统一数据层被替换为页面静态数据 | 页面之间难以一致，后续接后端无法沿用原型的接口边界 | 迁入原始 `DB + api` 结构或等价 React Store，并保持 16 个契约语义 |
| P1 | 分析能力退化 | 只能看静态比例，无法进行周期对比和识别隐性成本 | 恢复当期/上期、趋势、TOP5 与行业隐性成本 |
| P1 | 报表模块消失 | 管理者无法查看月报明细或执行导出 | 恢复月报列表、详情和导出交互 |
| P1 | 供应商与分类管理消失 | 采购与成本口径无法维护 | 恢复 CRUD、搜索、分组、颜色和占用校验 |

## 建议的恢复顺序

### 第一轮：恢复核心账本闭环（P0）

先建立统一的本地业务数据层，将五行业模板、流水、产品/服务项目、BOM、分类和供应商放入同一状态容器。随后在现有移动页面中恢复“记一笔 → 流水新增 → 流水详情/编辑/删除 → 概览与预算更新”闭环。完成后补入行业成本卡列表、详情、BOM 增删与成本重算。

### 第二轮：恢复分析和月度决策（P1）

将分析页扩展为本期/上期构成、趋势、TOP5 和行业隐性成本；新增月报列表与详情页，保留原型的成本明细、毛利统计与导出交互。

### 第三轮：恢复基础主数据维护（P1）

补入供应商和分类管理页，并实现搜索、分组、增删改与分类占用校验。这一轮完成后，移动 App 才能覆盖原始原型的主要经营闭环。

## 图表模块：必须保留的原始能力

原始版本的图表并非装饰，而是“看账—发现异常—进入处理页”的经营决策入口。其分析接口返回 `period`、`share`、`trend`、`top` 和 `suppliers` 五类数据，因此图表恢复必须与统一数据层一起进行，不能只用静态示意图替代。

| 原始图表 | 原始数据与交互 | 移动 App 中的保留位置 |
|---|---|---|
| 工作台近 6 月成本与收入图 | 成本/收入双系列柱状对比，点击进入分析 | 工作台保留一张紧凑趋势卡；点击进入“分析 → 趋势”二级页 |
| 本期/上期成本构成环图 | 环形分段、分类图例、金额与占比、周期切换 | 分析首页的第一张决策卡；点击分类进入成本卡/流水筛选 |
| 近 6 月趋势图 | 成本、收入、成本率趋势与月份数据点 | 分析首页下方；点击数据点显示金额、环比与异常说明 |
| TOP5 高成本实体排行 | 按行业显示商品/菜品/服务项目，点击进入成本详情 | 分析首页的排行区；点击进入行业成本卡详情 |
| 供应商支出排行 | 按供应商支出与趋势排序，点击进入供应商详情 | 分析页或“供应商”二级页；作为采购与议价入口 |
| 行业隐性成本卡与健康度环 | 行业公式、估算金额、占营收比例、健康度、分项进度条 | 分析页的独立“隐性成本”入口；详情展示口径、基准与改进提示 |
| 单位成本趋势 | 单个商品/菜品/服务项目的成本变化 | 行业成本卡详情页，与 BOM 和售价/毛利率并列展示 |

移动端的原则是**图表集中在“分析”一级 Tab，并通过详情页下钻**，而不是把所有图表堆在工作台。工作台只保留一张近 6 月迷你趋势卡和可操作的风险摘要；分析页负责周期切换、构成、趋势、排行和隐性成本；行业成本卡详情负责单位成本趋势与 BOM。

## 推荐的当前决策

建议**保留刚完成的移动 App 信息架构**，但立即停止继续堆叠展示型页面，转为按上述顺序迁入原始业务模块。这样既不会回到不适合手机的长页，又能恢复原型本来最有价值的成本核算能力。
