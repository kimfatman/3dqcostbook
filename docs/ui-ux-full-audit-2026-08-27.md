# 算得清移动端 UI/UX 全量审计

**审计日期：** 2026-08-27  
**审计范围：** 当前开发版一级页面、可深链接关键二级页面及核心宽屏状态。  
**截图基线：** 31 张 390px 手机全页截图、3 张 768px 平板截图、3 张 1280px 桌面截图，共 **37 张**；详细文件清单见 `manifest.json`，原图位于 `screenshots/`。

> **结论：** 产品已具备清晰的蓝白经营工具基调、可用的移动端信息架构和正确的数据/图表主线，但视觉系统尚未完全收束。当前最需要解决的不是再增加更多装饰或说明文字，而是**建立统一的表单、列表、空态与行动优先级规范**，并让首页与分析页的经营判断更快被读懂。

## 1. 审计方法与覆盖边界

本次审计采用消费级移动经营 App 的标准，关注首屏 3 秒可读性、核心行动的触达效率、金额/风险信息优先级、表单错误预防、列表扫描、空态可行动性、色彩对比、触控尺寸，以及 390px、768px、1280px 的布局连续性。截图均为真实当前页面，不补造数据、订单、退款或资料状态。

| 覆盖组 | 已采集页面 | 说明 |
| --- | --- | --- |
| 一级经营闭环 | 首页、订单、商品、经营分析、我的 | 390px 完整采集；首页、分析、记一笔另有 768px/1280px。 |
| 录入与流水 | 记一笔、经营流水、订单录入、退款空态、流水详情空态 | 商品销售入口、表单层级和防错页均已覆盖。 |
| 商品与成本 | SKU、成本卡新建、BOM、新智能定价、间接成本、成本卡详情 | 成本、售价、趋势和行动按钮均已审阅。 |
| 目标与资料 | 预算、目标归档、经营健康度、通知、行业切换、资料、头像、店铺品牌 | 资料三页在未登录/加载状态下仅可审阅状态框架。 |
| 管理与详情 | 报表、供应商、分类、新增供应商/分类、订单/报告详情空态 | 订单、流水、报告详情需选中真实对象后才能完整呈现，不能以无上下文空态代表全部详情体验。 |

## 2. 总体评价

| 维度 | 当前判断 | 主要证据 | 改进方向 |
| --- | --- | --- |
| 经营信息层级 | **基本成立** | 首页有经营主卡；分析页已有经营利润、利润构成、趋势和成本诊断。 | 进一步限制同屏同权重模块数量，先结果、后原因、再复核。 |
| 视觉一致性 | **中等** | 冷白背景、数字蓝、深海军蓝结果卡、圆角白卡已普遍使用。 | 表单、列表、详情、空态仍使用不同密度和不同按钮语法。 |
| 行动效率 | **中等偏好** | 悬浮记一笔、底部导航、订单录入、成本卡和智能定价路径清楚。 | 详情空态与无订单空态没有把下一步行动置于首屏。 |
| 数据可读性 | **中等** | 预算环、利润趋势、成本结构与排行均具备正确图形语义。 | 分析页和流水页的密度较高；需要更强的分组、扫描锚点和渐进展开。 |
| 表单可用性 | **存在 P0 缺口** | 新增供应商的跨行业复选框发生标签折行/方框孤立；表单说明样式不统一。 | 建立表单字段、复选、帮助文本和提交区的统一组件规范。 |
| 响应式体验 | **移动端良好，宽屏待强化** | 390px 各页未见横向裁切；768px/1280px 仍保留移动壳。 | 宽屏明确采用居中的移动工作台，或为分析页采用受控双列，避免空白被动放大。 |

## 3. 分级问题清单

### P0：应优先修复

| 编号 | 页面与可复现状态 | 观察到的问题 | 用户影响 | 建议的最小改动 |
| --- | --- | --- | --- | --- |
| P0-1 | 新增供应商，390px | “跨行业可用”标签被窄列拆开，复选框独立悬在右侧，文本、控件、状态不构成一个可扫读字段。 | 用户不容易判断复选框含义与选中状态；影响表单完成率和键盘/读屏对应关系。 | 将复选字段改为整行可点击的 `label`，用固定 20px 控件列 + 自适应文案列；说明置于同一字段下方，最小触达高度 44px。 |
| P0-2 | 订单详情、流水详情、退款、报表详情的无上下文状态 | 当前仅显示“对象不存在/请先选择”等一句提示，首屏其余区域留白，没有返回到订单、流水或报表列表的显式行动。 | 从通知、历史链接或误操作进入时形成视觉和操作死端。 | 统一为“当前结果—原因—下一步”空态；提供一个主要按钮回到来源列表，保留返回按钮作为次要退出方式。 |
| P0-3 | 成本卡详情 | “编辑成本 / 测算定价 / 删除”三项同权并排，删除仅以浅红区别且面积相近。 | 高风险删除动作与常用经营动作竞争，误触后果高。 | 保留编辑与测算定价为主/次两个可见按钮；删除进入更多菜单或二次确认底部抽屉，不改变删除校验。 |

### P1：本轮视觉收束的主要收益点

| 编号 | 页面 | 观察到的问题 | 建议 |
| --- | --- | --- | --- |
| P1-1 | 首页 | 默认“今天”无数据时，经营主卡的蓝色体量仍很强，但“没有已入账数据—下一步记一笔/商品销售”的行动弱于装饰和次级模块。 | 空态主卡改为结果、原因、双行动的账本状态；蓝色仅强调主结果和主要行动，不增加虚构经营数据。 |
| P1-2 | 经营分析 | 利润结论、利润桥、趋势、商品毛利、成本诊断、结构对照连续堆叠；信息正确但整体太长，白卡视觉重量趋同。 | 固定为“经营利润 + 利润桥”首屏；趋势与商品毛利形成一组；成本诊断默认显示结论和单个行动，结构/供应商置于渐进复核区。 |
| P1-3 | 经营流水 | 长列表的日期、来源、标签、金额和状态同时出现，缺少明显的日组或金额扫描锚点。 | 使用日期分组标题、右对齐等宽金额列、弱化非关键辅助行；保留既有搜索、月份、类型和精确下钻。 |
| P1-4 | 订单 | 无订单状态与常规列表视觉落差大，页面的“商品销售”入口不够强。 | 以“本期尚无商品销售订单”为结果标题，副文案说明联动收益，主按钮进入订单入账。 |
| P1-5 | 报表、供应商、分类 | 报表列表信息偏轻；供应商/分类列表中名称、金额、归属、编辑、删除同时争夺注意力，图标操作过轻。 | 报表增加一行净营收/经营利润速览；管理列表每行只保留一个主要进入点，将编辑与删除收束到行内更多操作。 |
| P1-6 | 智能定价 | 深色结果卡、深色趋势卡与白色模拟区交替，产品从蓝白经营工具切换为深色试算仪表。 | 维持深海军蓝只承载“当前建议/重要结果”；把趋势图和次级模拟统一回白卡/浅色网格，减少黑色块数量。 |
| P1-7 | 二级表单 | 成本卡、BOM、供应商、分类、间接成本的标题、辅助说明、字段间距、复选和底部提交区不完全一致。 | 抽取统一的二级表单头部、字段组、帮助文本、选择芯片和固定提交区规格；不要改变现有字段或验证逻辑。 |
| P1-8 | 平板与桌面 | 宽屏下仍采用窄移动壳，内容区与背景的关系不明确；分析页无法借助宽度提升图表和排行可读性。 | 选择单一策略：全局移动壳明确居中并增加低对比背景，或仅分析/流水在 768px 起使用最大 860px 的受控双列。 |

### P2：品牌与完成度优化

| 编号 | 方向 | 建议 |
| --- | --- | --- |
| P2-1 | 品牌语言 | 让深海军蓝结果、品牌蓝行动、浅灰账本背景贯穿所有皮肤；避免皮肤将产品语义改成纯玻璃拟态或科技舱。 |
| P2-2 | 行业身份 | 把行业分类、风险焦点和单位一致地嵌入订单、商品、分析和记一笔，而非仅在页头显示行业标签。 |
| P2-3 | 图表说明 | 保持 Tooltip 与关键数值，但删除重复解释句；图表标题用“结果/原因/排行”短语，空态提供单一下一步。 |
| P2-4 | 微交互 | 统一按钮按压、列表进入和展开的 160–220ms 反馈；键盘触发保持即时，并尊重减少动效。 |

## 4. 推荐实施顺序

第一批应先解决 P0-1 至 P0-3：表单复选框、详情空态行动和危险操作层级。这些改动均是展示与交互收束，不涉及账本聚合、金额精度、订单日期、退款日期、SKU 快照或成本定义。

第二批处理 P1-1 至 P1-3：首页今日空态、分析页渐进信息架构与流水扫描效率。它们最直接影响经营者每天进入产品后是否能在三秒内理解“今天结果是什么、为什么、下一步做什么”。第三批再统一二级表单和宽屏策略，最后进行皮肤、行业身份和动效的品牌完成度优化。

## 5. 验收标准

| 场景 | 通过条件 |
| --- | --- |
| 390px 表单 | 所有复选、选择、输入和提交控件不折行错位；标签与控件可作为一个字段整体点击；主按钮完整可见。 |
| 无对象详情 | 首屏同时提供对象缺失原因和可点击的回到来源列表行动；不再只有孤立提示。 |
| 分析首页 | 首屏能在三秒内读取经营利润、净营收、销售成本和费用；成本结构与供应商复核不抢占利润结论。 |
| 长列表 | 用户能快速找到日期组、金额、类型和下一步筛选；金额列对齐，非关键文本降级。 |
| 375–1280px | 无横向滚动、裁切或悬浮控件遮挡；宽屏布局有明确的居中或受控扩展策略。 |
| 业务不变量 | 金额继续以分存储并两位展示；订单按成交日、退款按退款日；SKU、成本、分类和供应商下钻语义保持不变。 |
