# 用户补充 UI 与数据问题核验

**核验日期：** 2026-08-27  
**证据：** 当前 `Home.tsx`、账本/图表聚合函数与当前开发版 390px 首页、经营分析原始截图。  
**原则：** 区分真实计算错误、不同期间/范围的展示混用、已存在但表达不足的能力，以及无法由当前源码复现的截图文字；不以推测改动账本。

## 当前截图补充观察

首页默认范围为“今天”，经营主卡与订单数使用当天数据；但下方月销售目标、经营提醒、最近动态、SKU 排行仍是“本月”或历史数据。这导致同一页同时出现“今天尚无已入账数据”“近 7 日无订单”和“日均预计月末 ¥246,048.15”，没有足够强的周期标签，属于可复现的信息架构问题。

销售动能标题区域同时出现内嵌提示旁的“近 7 日”和右侧“近 7 日”，形成重复时间标签。经营分析当前截图已经展示利润趋势的最新/最高/最低三项，成本结构也已经用环图、金额与占比图例呈现；用户提出的“完全没有峰谷/完全只有数字”的描述不适用于当前版本，但**真实事件标记尚未具备**。

## 调整后的建议顺序

第一批优先统一**范围和待办来源**：首页当前选择范围、月度预算、近 7 日销售趋势、月销售目标都必须用明显的周期标签；“优先处理”统一从一个待办聚合器中取最高项，再说明它属于今天、本周或本月。这个阶段不重算指标，只避免正确数字被错误对比。

第二批处理**数据与单位表达**：建立金额、百分比、数量、系统编码的显示令牌；修复重复“近 7 日”、提升辅助文字对比度、触发目标异常建议、补充商品排行字段契约、提供历史成本快照对比。

第三批再推进**导航、设置归类、图表事件与批量操作**。订单批量功能必须先确定允许的批量命令和审计规则；利润趋势事件只能显示真实可用事件，新的促销/价格变动事件模型需要单独定义。
