# 行业模板显示一致性审计

## 范围与口径

本次审计覆盖餐饮、零售、电商、美业服务、小商贩五个模板的用户可见实体名称、成本卡入口、SKU/项目页面、材料单位、资料页图片文案、预算与分析页的行业/分类信息来源。`SKU` 保留为技术性的销售库存单元标识；它不替代各行业的“菜品、商品、服务项目、货品”业务名称。

| 模板 | 业务实体 | 底部入口 | 默认单位 | 成本构成名称 |
|---|---|---|---|---|
| 餐饮 | 菜品 | 菜品 | 份 | 配方 |
| 零售 | 商品 | 商品 | 件 | 成本构成 |
| 电商 | 商品 | 商品 | 件 | 成本构成 |
| 美业服务 | 服务项目 | 项目 | 次 | 服务耗用 |
| 小商贩 | 货品 | 货品 | 件 | 进货构成 |

## 已核对并修复的显示路径

| 页面/入口 | 名称、分类、单位来源 | 状态 |
|---|---|---|
| 首页与底部导航 | 行业标题来自 `template.label`；成本卡 Tab 来自 `template.tabLabel` 或实体回退映射。 | 已覆盖 |
| 成本卡列表、新增、详情与图片 | 标题、列表、主操作、类型占位、图片操作均使用 `template.entityLabel`；配方/材料名称使用 `template.formulaLabel`。 | 已覆盖 |
| SKU 成本页 | 页面标题来自实体成本标题；订单数量显示使用每个 SKU 的 `unit`。 | 已覆盖 |
| 材料编辑 | 新增行默认数量和占位来自 `template.unitLabel`；编辑成本卡时保留既有材料数量。 | 已覆盖 |
| 资料页 | 成本卡图片说明使用当前行业实体名称。 | 已覆盖 |
| 预算与分析 | 预算、月报与分析指标采用经营通用名称；分类显示直接读取当前行业 `categories`，不会共享其他行业分类。 | 已核对，无固定商品名称 |

## 尚需生产业务数据验证的路径

订单页仍有少数以“SKU”呈现的技术字段；后续将在真实已登录业务数据下，逐项验证渠道履约单位、订单成本说明与退款文本是否全部采用当前销售单元，而不是默认“件”。该项被保留在待办，不能据本次本地静态审计关闭。

## 材料输入根因

材料行过去将材料名称拼入 React `key`，每输入一个字符就会改变行身份并重建输入框。现已改用仅存在于草稿层的稳定材料 ID；保存时会剥离该 ID，因此不会改变 BOM 持久化 ID、SKU 成本或历史订单快照。
