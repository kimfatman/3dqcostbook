# 苹果移动端 UI 对比调研：已核验观察

## 外部基准

苹果官方 HIG 明确要求将重要内容置于阅读顺序的靠前位置、用对齐和分组建立层级，并让导航作为独立于内容的功能层。[1] 苹果对材料的当前建议也强调：动态玻璃材质属于导航与控件层，不应扩散到内容层；内容层应使用稳定、语义化的材料来保持清晰。[2]

Apple 的排版规范推荐用字号、字重和颜色建立层级，尽量减少字体数量，并让重要内容在字号变化后仍保持优先；iOS/iPadOS 默认文字规格为 17 pt、最小为 11 pt。[3] 可访问性规范同时要求小文字满足足够对比，并让颜色之外的图形、文字或形状共同承担状态表达。[4]

## 当前算得清界面

| 页面 | 已体现的优点 | 与苹果体系存在的可优化差距 |
|---|---|---|
| 经营首页 | 顶部品牌、经营利润、产品宣传、趋势、预算和第一成本有稳定的纵向阅读顺序；底部五 Tab 清晰。 | Logo、提醒跑马灯、期间标题、利润卡、Banner 在首屏集中，工具层和内容层的区分可更强；小辅助数字与图表刻度偏小，未建立系统级文字等级。 |
| 消息中心 | 风险提醒已采用“金额结果 → 原因 → 行动”结构，支持下钻和已读。 | 列表中的业务层级、图标权重和行动标签仍可进一步向 iOS grouped list 的信息密度与触控间距靠拢。 |
| 订单 / 商品 | 订单的空状态与商品卡的金额对齐均具有明确业务目的；等宽金额已开始应用。 | 商品卡信息密集、卡片内部层级多；可降低同时出现的容器、边框、网格和小标签数量，用分组、间距、行高与层级承担更多组织任务。 |

## 设计边界

算得清不应直接复制 iOS 的 Liquid Glass 外观。它是 Web App，且“账本蓝图”网格、页签、等宽财务数字与行业化成本口径是产品识别资产。可借鉴的是苹果的**内容优先、功能层/内容层分离、动态字号、控件克制和一致动作反馈**；不宜用半透明玻璃、模糊和圆角胶囊覆盖所有经营卡片。[2]

## 证据矩阵

| 对比维度 | 苹果官方依据 | 对算得清的解释 |
|---|---|---|
| 信息层级 | HIG Layout 要求重要内容前置，并通过对齐与分组提升可扫描性。[1] | 经营判断必须在 Banner 之前完整呈现；当前已符合方向，但可进一步减少顶部并列信息。 |
| 排版与数值 | HIG Typography 要求用字号、字重与颜色表达层级，避免过多字体，并支持可读性与字号适配。[3] | 保留 IBM Plex Mono 作为金额字体；建立统一数值、列表、说明三档文字比例，提升小字可读性。 |
| 导航 | HIG Tab Bars 将 Tab 定义为一级区块导航，而非页面操作入口。[5] | 经营、订单、商品、分析、我的五 Tab 的信息架构正确；新增动作应继续放在页面内容与拇指区。 |
| 材料与容器 | HIG Materials 规定功能控件/导航层与内容层职责分离，动态材质应克制使用。[2] | 可让顶部栏和底部 Tab 更具“浮于内容之上”的层感；经营卡和商品列表仍使用稳定的账本内容表面。 |
| 动效与控制权 | WWDC26 将“能动性”定义为让用户掌控，并强调即时自然反馈；自动化不得压过用户意图。[6] | Banner 的暂停控制和减少动态回退是正确做法；经营提醒不应自动强制跳转或抢焦点。 |
| 无障碍 | HIG Accessibility 建议支持更大字号、足够对比、44×44 pt 控件，并避免仅依赖颜色传达状态。[4] | 优先修复趋势轴、说明文字与筛选标签的可读性；风险继续同时使用文字、符号与颜色。 |
