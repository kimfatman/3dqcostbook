## 二、全局性问题（P0）

### G1：洞察页两层嵌套折叠，层级混乱
**严重度：P0**

洞察页"成本与结构复核"是一个折叠区域（默认收起），里面包含 7+ 个卡片：
- 成本诊断
- 成本分析饼图
- 行业参考估算（**又是一个折叠区域，嵌套在内层**）
- 经营控制（经营控制+经营报表两个子卡片）
- 销售目标
- 成本结构变化
- 供应商排行

**问题：**
1. 两层嵌套折叠（外层"成本与结构复核"→内层"行业参考估算"），用户需要点击两次才能看到内容
2. 外层折叠默认收起，但里面包含 7+ 个重要卡片（销售目标/供应商/结构对比），用户可能完全不知道这些内容存在
3. 折叠区域只显示标题+描述，没有内容预览（如"包含7项分析"），可发现性极差
4. "行业参考估算"作为内层折叠，嵌套在外层折叠中，层级过深

**Apple Design 违反：** 空间一致性（§7）— 折叠区域应该 originate from its source，但这里折叠区域与内容的空间关系不明确；直接操作（§2）— 用户无法直接看到内容，需要多次点击。

**优化方案：**
1. **取消外层"成本与结构复核"折叠**，将里面的 7 个卡片按逻辑分组，直接平铺显示
2. 新增分组标题："成本与结构"（包含成本诊断/成本结构/结构对比/供应商）、"目标与控制"（包含销售目标/经营控制/经营报表）
3. "行业参考估算"保留折叠，但从外层折叠中移出，作为独立卡片放在"成本与结构"分组末尾
4. 折叠区域加内容预览："包含3项潜在漏损估算"

### G2：折叠/展开默认状态不统一，无规范
**严重度：P0**

当前折叠默认状态混乱：
- "成本与结构复核"：默认收起（但包含7+重要卡片）
- "行业参考估算"：默认收起
- 健康度评分公式（details）：默认收起
- 结构对比"查看全部"：默认收起（>3类时）
- 记录表单"更多信息"：默认收起
- 健康度维度列表：默认展开
- 预算预测：默认展开
- 订单搜索框：默认收起

**问题：**
1. 没有统一的折叠默认状态规范（什么内容默认收起，什么默认展开）
2. "成本与结构复核"包含重要内容却默认收起，而健康度维度列表（次要内容）默认展开，优先级颠倒
3. 用户无法预测哪些内容是折叠的，可发现性差

**ui-ux-pro-max 违反：** 可发现性（Priority 9）— 折叠内容应该有明确的视觉提示和内容预览。

**优化方案：** 制定折叠默认状态规范：
- **默认展开**：核心业务数据（利润概览/销售目标/成本诊断/健康度维度）
- **默认收起**：次要/辅助信息（行业参考估算/评分公式/更多信息/查看全部）
- **折叠区域必须有内容预览**：如"包含3项估算"、"共8类"
- **折叠区域必须有视觉提示**：ChevronDown 图标 + 标题 + 描述 + 内容数量

### G3：分组标题缺失，信息密度过高无组织
**严重度：P0**

当前只有洞察页有 2 个分组标题（"经营利润"、"趋势与商品毛利"），其他页面均无分组标题：
- 工作台：8+ 卡片直接堆叠（经营概览/销售动能/成本结构/销售目标/SKU排行/经营待办/促销轮播）
- 订单页：订单列表+售后处理+退款帕累托直接堆叠
- 商品页：商品列表+KPI卡片直接堆叠
- 我的页：身份卡+店铺管理+设置+账户直接堆叠

**问题：**
1. 用户一屏看到大量卡片，无法快速定位目标内容
2. 没有视觉分组，信息架构不清晰
3. 卡片顺序没有逻辑（如工作台经营概览后直接是销售动能，没有"经营概览"分组）

**Apple Design 违反：** 理解（人类需求第2项）— 分组标题帮助用户理解信息结构；空间一致性（§7）— 相关内容应该在空间上分组。

**优化方案：** 所有页面增加分组标题：
- 工作台："经营概览"（利润概览+销售动能）、"成本与目标"（成本结构+销售目标）、"商品与待办"（SKU排行+经营待办+促销轮播）
- 订单页："订单列表"、"售后与退款"（售后处理+退款帕累托）
- 商品页："商品列表"、"成本概览"（KPI卡片）
- 我的页："账号与店铺"（身份卡+店铺管理）、"设置"（资料/皮肤/行业/预算）、"账户"（退出登录）
- 分组标题样式：12px 加粗 + 左侧品牌色竖条 + 上下间距 12px（与现有 analysis-group-title 统一）

### G4：导航层级返回逻辑硬编码，不灵活
**严重度：P1**

handleBack 函数中有大量 if-else 硬编码返回逻辑：
```
subPage==="refundForm" → setSubPage("orderDetail")
subPage==="bomForm" → setSubPage("cardDetail")
subPage==="pricing" → setSubPage("cardDetail")
subPage==="cardForm" → setSubPage("cards")
subPage==="record" → setSubPage("records")
subPage==="recordDetail" → setSubPage("records")
...
```

**问题：**
1. 如果导航层级变化（如新增一个中间页面），需要修改多处硬编码
2. pageStack 已经记录了导航历史，但 handleBack 没有使用 pageStack 自动返回，而是硬编码
3. 部分页面返回逻辑可能不正确（如从订单详情进入退款表单，返回应该回到订单详情，但如果是从其他地方进入呢？）

**优化方案：**
1. 使用 pageStack 自动管理返回：`const prev = pageStack[pageStack.length-1]; setTab(prev.tab); setSubPage(prev.subPage); setPageStack(stack => stack.slice(0,-1));`
2. 保留特殊情况的硬编码（如需要跳过中间页面），但默认使用 pageStack
3. 新增页面时不需要修改 handleBack，自动支持返回

## 三、逐界面详细审查

### 3.1 工作台（home）

**当前结构（8+ 卡片直接堆叠，无分组标题）：**
1. 经营概览（蓝色大卡：利润/收入/成本/费用）
2. 销售动能（柱状+折线图）
3. 成本结构（环形图）
4. 销售目标（环形进度+子弹图）
5. SKU销量排行（条形图）
6. 经营待办（通知列表）
7. 促销轮播（3个slide）
8. FAB（记一笔，浮动）

**问题：**
1. ❌ 无分组标题，8+卡片直接堆叠，一屏显示不完
2. ❌ 卡片顺序逻辑不清晰：经营概览→销售动能→成本结构→销售目标→SKU排行→经营待办→促销轮播
3. ❌ 促销轮播与经营数据卡片混在一起，视觉权重过高
4. ❌ 经营待办（通知）放在底部，用户可能错过
5. ⚠️ FAB 遮挡底部内容（已修复 padding-bottom: 96px，但仍需验证）

**优化方案：**
1. 新增分组标题：
   - "经营概览"：经营概览 + 销售动能
   - "成本与目标"：成本结构 + 销售目标
   - "商品排行"：SKU销量排行
   - "待办与活动"：经营待办 + 促销轮播
2. 调整卡片顺序：经营概览→销售动能→成本结构→销售目标→SKU排行→经营待办→促销轮播（按业务优先级排序）
3. 促销轮播改为紧凑卡片（高度减半），或放在页面最底部
4. 经营待办放在"经营概览"分组后（提高优先级）

**当前结构（13+ 卡片，2 个分组标题，2 层嵌套折叠）：**

   - 成本诊断
   - 成本分析饼图
   - 折叠"行业参考估算"（嵌套内层）
   - 经营控制（经营控制+经营报表）

   - "目标与控制"：销售目标 + 经营控制 + 经营报表
   - "现金流与健康"：成本趋势 + 现金流收支 + 经营健康度
3. **"行业参考估算"保留折叠**，但从外层折叠移出，放在"成本与结构"分组末尾，加内容预览"包含3项潜在漏损估算"
4. **经营健康度维度列表改为可折叠**（默认展开前3维，其余折叠"查看全部5维"）
5. **卡片顺序按业务逻辑排序**：利润→趋势→成本→目标→现金流→健康度

- 优化：三按钮改为两按钮（编辑成本/测算定价），删除移到编辑页底部

**记录表单（record）：**
- 结构：标题 + 交易类型 + 金额 + 日期 + 分类 + 折叠"更多信息"（供应商/备注/凭证）+ 保存按钮
- 问题："更多信息"折叠包含供应商/备注/凭证，其中凭证是重要功能，不应该折叠
- 优化：凭证上传从"更多信息"移出，放在分类后面（默认展开）；"更多信息"只包含供应商/备注

**退款表单（refundForm）：**
- 结构：标题 + 退款数量 + 退款金额 + 手续费 + 原因 + 回收状态 + 日期 + 确认按钮
- 问题：7 个字段直接堆叠，无分组；可分为"退款信息"（数量/金额/手续费/原因）和"退货回收"（回收状态/日期）
- 优化：新增分组标题"退款信息"、"退货回收"

## 四、折叠/展开组件规范（新增）

### 4.1 默认状态规范

| 内容类型 | 默认状态 | 示例 |
|---|---|---|
| 核心业务数据 | 展开 | 利润概览/销售目标/成本诊断/健康度维度 |
| 次要/辅助信息 | 收起 | 行业参考估算/评分公式/更多信息 |
| 长列表（>5项） | 收起前5项 | 结构对比>3类/供应商>5个 |
| 筛选/搜索 | 收起 | 订单搜索框 |
| 批量操作 | 隐藏（触发时显示） | 订单批量工具栏 |

### 4.2 折叠区域必须包含

1. **触发按钮**：整行可点击，ChevronDown 图标（收起时）/ ChevronUp（展开时）
2. **标题**：≤8字，加粗 14px
3. **描述**：≤20字，12px tertiary
4. **内容预览**：如"包含3项估算"、"共8类"、"2项待核对"
5. **展开/收起动画**：height + opacity 过渡，0.3s spring

### 4.3 折叠区域禁止

1. ❌ 禁止嵌套折叠（折叠区域内不再包含折叠区域）
2. ❌ 禁止核心业务数据默认收起
3. ❌ 禁止折叠区域无内容预览
4. ❌ 禁止折叠区域触发按钮只有图标无文字

## 五、分组标题规范（新增）

### 5.1 分组标题样式

- 字号：12px 加粗
- 颜色：--sdq-text-secondary
- 左侧：3px × 12px 品牌色竖条（--sdq-action-primary）
- 间距：上方 16px，下方 8px
- 样式类：.section-group-title（与现有 analysis-group-title 统一）

### 5.2 分组标题命名规范

- ≤6字
- 名词短语，不用动词
- 按业务逻辑分组，不按页面位置
- 示例："经营利润"、"成本与结构"、"目标与控制"、"售后与退款"
