登录页设计评审报告

算得清 · app.3dq.site · SelfHostedAccessGate.tsx · 评审日期 2026-08-30
方法：Playwright 双视口截图 + DOM 程序化审计 源码通读 170 行 AutoGLM 图像识别（390/1280） 发现 14 项：P1×2 · P2×6 · P3×6

结论概要

登录页完成度较高、SaaS 调性正确、安全与可访问性基础扎实（autocomplete 全套、role=alert、OTP 全流程、失败冷却）。主要问题集中在三处：① 一个构建缺陷——分析脚本占位符未解析，全站每页报 HTTP2 协议错误且访问统计失效；② 触控与对比度的可达性短板——Tab 高度 34px、四处文字对比度低于 AA、无密码可见切换、无协议同意环节；③ 桌面端「移动壳居中投屏」——1280px 下 343px 窄卡居中，两侧大留白失衡。

评审方法披露：对比度采用「文字色 vs 最近非透明祖先背景」近似计算；深蓝面板内白字的 1.07 读数属算法假阳性已剔除，仅采信浅底文字读数。注册流程未实际提交表单（避免污染生产数据）。

P1 · 应立即修复

P1-1 分析脚本占位符未解析，全站每页报 HTTP2 协议错误

证据：Playwright 六个页面上下文全部捕获 GET https://app.3dq.site/%VITE_ANALYTICS_ENDPOINT%/umami :: net::ERR_HTTP2_PROTOCOL_ERROR

根因：client/index.html:14 使用 CRA/Vue CLI 风格的 %VAR% 占位符（继承自 project template，template.json 同款），Vite 构建不替换该语法，原样进入产物

影响：控制台错误污染排障；umami 访问分析完全失效，运营无数据

修复：接入 umami 前移除该行；接入时改用 import.meta.env.VITE_ANALYTICS_ENDPOINT（vite define 或构建期 HTML 转换），未配置时整段脚本不输出

P1-2 登录方式三 Tab 平铺拥挤，触控热区不足

证据：DOM 实测三 Tab 高度 34px、字号 11px（390px 视口）；图像评审判定「过于拥挤、文字压缩折行风险、点击热区过小」

修复：合并为「密码登录 / 验证码登录」两维度（验证码内再选邮箱或短信），Tab 高度 ≥44px

P2 · 体验与可达性（6 项）

编号问题修复建议
P2-1触控目标不足：方式切换按钮 36px、注册/找回入口 36px（Apple HIG ≥44px）高度 ≥44px 或扩大热区
P2-2文本对比度不足 4 处（AA 4.5:1）：card-foot 10px→2.42:1、副题 10px→3.17:1、11px 标签→3.8:1×2、access-switch 品牌蓝 12px→3.91:1文字加深一档或提升字号；switch 是注册/找回主入口必须达标
P2-3密码无显示/隐藏切换（8 位+长密码短语易输错）Field 增加 eye toggle
P2-4注册/初始化无服务协议与隐私政策同意环节（页脚仅一句话，个保法合规缺口）注册表单加勾选 + 协议链接
P2-5垂直节奏不均：标题区上下留白压抑、hero 与卡片 Z 轴关系弱标题-Tab 间距 20→28-32px，卡片阴影加深
P2-6品牌资产不一致：用通用 lucide 图标（Store/ShieldCheck），未用官方品牌印鉴（app 内已落官方 mark）替换为官方店铺印鉴，延续蓝图语言

P3 · 打磨项（6 项）

编号问题与建议
P3-1桌面端「移动壳居中投屏」：1280px 下 343px 窄卡居中、大留白失衡（头重脚轻）。建议左右分栏：左品牌区 50–60%（产品渲染图/数据插画/社会证明），右功能区输入框加宽至 360–400px
P3-2Hero 卖点胶囊（专属工作区/私有数据）在转化场景属干扰信息 → 移除或下放 onboarding
P3-3主按钮「登录并继续经营 →」移动端偏长（7 字+图标）；桌面评审认为场景感值得保留 → 移动缩短、桌面保留
P3-4输入框左侧 icon 颜色较深抢 placeholder 焦点 → 透明度降至 30–40%
P3-5底部备案文字 10px 过小过浅（合规信息需可读）→ ≥11px 且达 AA
P3-6工程细节：OTP 冷却计时器卸载未清理；登录首字段无 autoFocus（桌面）；login/register/recover 为组件状态不可深链寻址
