# 算得清 · 界面功能层级表（IA + 功能清单矩阵）
**日期：** 2026-09-01 ｜ **版本：** V1.0 ｜ **用途：** 全局功能地图，方便后续加功能时定位挂载点
**设计圈最常用表型：** 信息架构表（Information Architecture）+ 功能清单矩阵（Feature Inventory Matrix）

---

## 一、设计圈常用表型说明

| 表型 | 用途 | 适用场景 | 本项目采用 |
|---|---|---|---|
| **信息架构表（IA）** | 展示页面层级、功能归属、入口路径 | 全局功能地图、新功能挂载定位 | ✅ 采用 |
| **功能清单矩阵** | 功能×页面×优先级×状态，横向对比 | 需求排期、进度追踪、覆盖率检查 | ✅ 采用 |
| 站点地图（Sitemap） | 树状页面结构，纯页面层级 | 网站导航设计、SEO | 部分覆盖（IA表含页面层级） |
| 用户流程图（User Flow） | 用户操作路径，含判断分支 | 交互设计、走查验证 | 不采用（按需单独画） |
| 页面状态表 | 页面×状态（空态/加载/错误/正常） | 前端开发、测试用例 | 不采用（按需单独画） |

**为什么选 IA + 功能清单矩阵：** 加功能时最需要知道的是"这个功能挂在哪个页面下、入口在哪、和哪些功能平级、优先级是什么"，这两张表正好覆盖。

---

## 二、信息架构表（IA）

### 层级说明
- **L1 一级入口**：底部 Tab 导航（5个）
- **L2 二级页面**：从一级入口进入的列表页/设置页

## 四、加功能规范（新功能挂载指南）

新增功能时，按以下步骤定位挂载点：

### 步骤1：确定功能归属的 L1 一级入口

| 如果新功能是… | 挂到 |
|---|---|
| 看数据/概览/待办/快捷操作 | 工作台（home） |
| 订单相关（交易/退款/客户） | 订单（orders） |
| 商品/菜品/服务/BOM/定价/库存 | 商品（cards） |
| 分析/报表/诊断/目标/预算 | 洞察（analysis） |
| 设置/资料/供应商/分类/账户 | 我的（profile） |
| 跨页面全局能力（搜索/通知/AI） | 全局（顶部栏/FAB） |
| 独立流程（登录/支付/分享） | 独立页面 |

### 步骤2：确定 L2/L3 层级

- **L2 列表页**：如果新功能是一类数据的集合展示（如"供应商列表""优惠券列表"），作为 L2
- **L3 详情/表单页**：如果新功能是单条数据的查看或编辑（如"供应商详情""新增优惠券"），作为 L3
- **L4 操作**：如果新功能是页面内的一个按钮/弹窗/抽屉（如"导出按钮""批量删除弹窗"），作为 L4

### 步骤3：在 IA 表和功能清单矩阵中登记

- 在 IA 表对应 L1 下新增一行，填写 L2/L3/L4、功能操作、入口、数据依赖
- 在功能清单矩阵新增一行，分配 FID、填写功能名称、所属页面、层级、优先级、状态
- 优先级定义：P0=核心流程阻断 / P1=重要体验 / P2=增强功能 / P3=锦上添花

### 步骤4：确认数据依赖和入口

- 数据依赖：新功能需要哪些数据表/状态？在 cost-book.ts 中是否已有？
- 入口：用户从哪里进入这个功能？（Tab / 列表页按钮 / FAB / 设置页 / 详情页更多菜单）
- 出口：用户完成后回到哪里？（返回上一页 / 留在当前页 / 跳转到结果页）

### 步骤5：确认皮肤兼容性

- 新功能的颜色/样式必须使用 `--sdq-*` 语义令牌，禁止硬编码颜色
- 在 5 种皮肤（soft/deep/aurora/midnight/forest）下验证显示正常
- 深色模式下文字对比度 ≥4.5:1
