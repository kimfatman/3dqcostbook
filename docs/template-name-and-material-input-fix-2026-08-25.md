# 模板名称与成本卡材料输入修复记录

## 根因

新增成本卡的材料行此前使用 ``${index}-${material.name}`` 作为 React `key`。材料名称每输入一个字符就会改变该 `key`，导致对应行与输入框被卸载后重建，从而表现为焦点中断、无法连续输入或明显卡顿。

## 修复

材料草稿现在使用只存在于表单内的稳定 `id`。材料名称、金额、规格、数量的更新均按该 `id` 定位；保存成本卡时会显式剥离草稿 `id`，不改变既有 BOM 持久化标识或 SKU 成本计算。

同时，成本卡页面标题、底部 Tab、列表名称和资料页说明统一由行业模板的实体名称派生。餐饮显示“菜品”，零售/电商显示“商品”，美业显示“项目/服务项目”，小商贩显示“货品”。

## 本地交互证据

在 390px 本地预览的电商新增成本卡页，材料名称输入框已连续写入“包装盒加强版”；输入框保持可见焦点，页面仍停留在同一材料行，未发生按键后节点重建或页面跳转。
