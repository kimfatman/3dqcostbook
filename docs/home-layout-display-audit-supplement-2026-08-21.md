# 首页布局显示专项审计补充

**范围：** 首页“经营”Tab，当前真实账本状态；375 × 812、390 × 844、430 × 932 全页，以及 375 × 812 首屏与固定底部导航。  
**说明：** 本文只讨论**布局与显示结构**，不重复前一份报告中的数据口径与文案问题。

## 布局结论

三档视口均没有横向溢出、文本裁切或底部导航遮挡；基础响应式是合格的。但首页仍存在明显的**纵向节奏失衡**：最需要推动经营动作的“月目标”和“销售动能”在默认状态下各占一张等权白卡，造成首屏在主结果之后快速堆叠两段空白；相反，承载实际经营判断的成本结构与预算路径被推到更后面。问题不在某一个像素，而在“模块高度与经营优先级没有同步”。

| 项目 | 375px | 390px | 430px | 判断 |
|---|---|---|---|---|
| 横向溢出 | 未见 | 未见 | 未见 | 通过 |
| 顶栏 / 主结果对齐 | 稳定 | 稳定 | 稳定 | 通过，但首屏信息偏密 |
| 白卡宽度与边距 | 稳定 | 稳定 | 稳定 | 通过，但模块高度偏平均 |
| 底部五级导航 | 可见且未遮挡内容 | 全页图中按固定元素隐藏 | 全页图中按固定元素隐藏 | 首屏通过；需保留底部安全区回归测试 |
| Banner 文案安全区 | 可见 | 可见 | 可见 | 通过，但控件触控尺寸不足 |

## 布局问题清单

| 优先级 | 问题 | 显示证据 | 影响 | 布局修正方向 |
|---|---|---|---|---|
| **P1** | 默认状态下，主结果后连续出现“月销售目标”和“销售与商品动能”两张约等高空状态卡。 | 375/390/430px：主结果卡之后到成本结构前共有两段大面积说明性留白。 | 成本与预算风险被下推；用户需要滚动才能看到成本结构，而“未设目标、无订单”并不需要两张等权容器。 | 合并为一个**销售基线缺口模块**：上半行显示“目标未设”，下半行显示“SKU 订单 0 笔”，只保留一个 44px 主操作“记录第一笔 SKU 订单”；“设置目标”降为次级文本入口。可减少约一张卡的高度。 |
| **P1** | 首屏纵向阅读链过长，且“经营亏损 → 预算风险 → 销售缺口 → 商品缺口 → 成本结构”之间没有紧凑的因果分组。 | 375px 首屏：在底部导航上方看到主结果、目标卡、动能卡，成本结构仅出现在首屏外或底边。 | 移动端用户不能在一次停留中完成“结果 + 最重要原因 + 行动”的判断。 | 将主结果卡底部的预算动作作为唯一优先路径；销售缺口改为折叠的账本行。确保 375px 首屏至少露出成本结构标题或第一成本行。 |

| **P1** | 成本结构卡的环图与右侧三行分类列表处于同一高度，但列表行的上下边界和环图中心基线未形成强对齐。 | 375/390/430px：环图视觉中心略低于第一成本行，总体像“图 + 另一张小列表”。 | 降低“同一账页”的可扫读性；宽屏时留白增加但信息关系没有更紧密。 | 以环图中心作为三行列表的垂直中轴，使用固定 `grid-template-columns: 104px 1fr`（375px 可降到 96px），右侧行高一致并统一右对齐百分比与箭头列。 |

| **P2** | Banner 的轮播圆点与暂停按钮视觉及触控面积偏小，且贴近右下角。 | 三档底部 Banner。 | 小屏单手触控不稳定；控件被 3D 产品元素和深色背景吞没。 | 将圆点、暂停收进至少 44 × 44px 的透明触控容器，固定在 Banner 右下安全区；375px 下避免与产品图形重叠。 |
| **P2** | 顶栏的品牌、提醒、未读数量共处一行；375px 下提醒文案与徽标紧凑，行业条与主结果之间也留有一段无任务的断层。 | 375px 首屏。 | 顶部从品牌到经营判断缺少明确的节奏：既不像工具栏，也不像经营摘要。 | 顶栏固定为品牌和消息入口；把长提醒移至行业条下方的单行风险带，或将行业条与提醒合并成“电商｜月末预计超预算”的 44px 行，使主结果卡更早出现。 |

## 建议的首页垂直结构

```text
品牌 + 消息入口
行业 / 当前最高风险（单行）
主结果：结果 → 预算原因 → 唯一优先行动

销售基线缺口（目标 + SKU 订单合并为一张紧凑账本模块）
成本结构（环图 + 第一成本行）

产品宣传 Banner（低优先级）
底部五级导航
```

## CSS 与组件调整路径

| 调整对象 | 建议改动 | 预期收益 |
|---|---|---|
| `HomePage()` 的默认无订单分支 | 合并 `SalesTargetProgress` 的未设目标状态与 `home-sales-gap` 为一个 `SalesBaselineGap` 组件；目标编辑保留为次级动作。 | 缩短首屏、建立单一主行动。 |
| 首页模块容器 | 定义 `--home-section-gap-major`、`--home-section-gap-minor`、`--home-card-compact-height`，取代均匀卡片间距。 | 用节奏表达经营优先级。 |
| 成本结构组件 | 采用固定图/表两列和行级网格，百分比、箭头统一到同一列。 | 提高横向扫读与跨宽度稳定性。 |
| Banner 控件 | 使用单独的 44px 控件层；产品图放在非交互区。 | 改善触控安全区。 |
| 顶栏与行业条 | 将经营提醒从极小标题行转为可见风险带；行业条承担行业身份与风险。 | 减少顶栏拥挤，提升首屏判断速度。 |
| ≥414px 断点 | 扩大财务列、成本列表和模块内间距，而不是仅扩大外部白卡。 | 让 430px 宽屏获得实际信息收益。 |

## 先后顺序

1. 合并默认状态的两张空卡，并把预算风险作为唯一主行动。
2. 重排主结果、销售基线与成本结构，使 375px 首屏露出成本结构标题或第一成本行。
3. 固化成本结构的两列对齐与模块间主次间距。
4. 最后调整顶栏风险带、Banner 控件安全区和 ≥414px 增量布局。

> 以上问题是独立的布局缺陷，不依赖前一份报告中的“成本总额与分类成本显示口径”问题；两类问题应并行处理，但 P0 口径显示仍应优先修正。
