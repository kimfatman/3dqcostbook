# 首页“本期经营”主卡：信息审计与时间范围实施记录

> 本文记录已确认并实施的设计与数据口径。**本次仅改首页展示与范围读取，不修改账本数据、金额计算、订单/退款日期归属或历史聚合逻辑。**

## 结论摘要

当前主卡能够同时呈现经营结果、净营收、总成本、利润率和优先处理事项，但其时间语义固定为“本月”，而文案、数字符号和风险事项之间存在可能造成误读的层级问题。尤其在亏损情形中，主金额使用绝对值而以“经营亏损”作小标签，用户需要主动结合公式和负的利润率才能理解这是亏损；这不适合作为第一眼经营判断。

主卡已改为**可切换的经营概览单元**：顶部提供“今天／本周／本月”三档选择，默认“今天”。核心结果、等式、成本率、利润率、对比项、订单数、客单价和退款影响同步采用同一范围。销售趋势、销售目标、提醒、轮播和 SKU 排行继续保留各自已经标明的时间范围，避免一个筛选器暗中改变整页不同语义的图表。

## 已确认实施决策

| 项目 | 已实施决定 |
| --- | --- |
| 首次进入默认范围 | **今天**。当天没有已入账数据时，主卡显示真实行动空态，不显示虚构的零利润健康结论。 |
| 首期范围 | **今天／本周／本月** 三项；不包含自定义或近 7 日的主卡筛选。 |
| 对比标签 | 按范围同步显示 **较昨日／较上周同期／较上月同期**。 |
| 亏损显示 | 主金额和核算结果均带负号，并以“经营亏损”明确说明；不再用无符号金额单独配亏损标签。 |

## 当前显示问题

| 优先级 | 观察问题 | 用户可能产生的理解偏差 | 建议方向 |
| --- | --- | --- | --- |
| P0 | 主金额在亏损时显示绝对值，结果标签才说明“经营亏损”。 | `¥8,284.00` 容易被扫读为正向收益；而公式、利润率分别显示亏损，三个区域需要用户自行校验。 | 亏损时将“亏损”与金额视为同一个结果，例如 **亏损 ¥8,284.00**；金额使用风险红但保留非颜色文字。盈利时显示“经营利润 ¥…”。 |
| P0 | 顶部写“本期经营”，主结果写“本月经营利润”，但没有选择范围或完整日期。 | “本期”与“本月”是否同义不明确；用户不能快速查看今天或本周。 | 顶部改为明确范围名称与日期，例如“本周 · 8 月 24–27 日”。 |
| P1 | “较上月”对今日或本周没有意义；当前月中与完整上月相比也不公平。 | 用户可能把不同长度的区间比较为真实增长或下滑。 | 比较项按范围更名为“较昨日”“较上周同期”“较上月同期”或“较上一等长区间”。 |
| P1 | “成本率”“利润率”没有显示分母，且净营收为零时显示 `0%`。 | 用户无法立即判断比率基于什么；无营收时 `0%` 容易被理解为健康。 | 以短标签明确为“成本 / 净营收”“经营利润 / 净营收”；分母为零时显示 `—` 并在按需提示中说明“暂无净营收，无法计算比例”。 |
| P1 | 行业通用提示紧贴主结果，底部又有一条可点击优先处理事项。 | 行业提醒可能被当作本期间数据结论；风险语义与底部行动重复。 | 主卡仅保留由当前范围真实数据得出的优先事项；行业通用关注点移至提醒模块或标注为“行业关注”。 |
| P2 | 等式区、比率区和底部行动信息丰富但视觉同权。 | 第一眼不能稳定锁定“赚/亏多少、相对前期如何、下一步做什么”。 | 固定阅读顺序为：**范围 → 结果 → 计算式 → 比率/对比 → 一个优先行动**；无优先事项时不保留空白行动栏。 |

## 推荐的时间选项与交互

已使用移动端可横向完整展示的三项分段按钮，默认选中**今天**。控件位于主卡顶栏，长度不超过一行；每项具有键盘焦点与 `aria-pressed` 选中状态。

| 选项 | 显示名称 | 当前区间（含首尾） | 对比区间 | 结果标签示例 |
| --- | --- | --- | --- | --- |
| 默认 | 今天 | 设备本地业务日期的 00:00–23:59 | 前一自然日 | `较昨日` |
| 已上线 | 本周 | 本周一至今天，按设备本地业务日期计算 | 上周一至上周同一星期几 | `较上周同期` |
| 已上线 | 本月 | 当月 1 日至今天 | 上月 1 日至上月同一日；月份天数不足时取月末 | `较上月同期` |

为控制首版复杂度，本期仅交付“今天／本周／本月”三个即时选项。自定义时间和近 7 日均未进入本次主卡范围，后续如需加入应作为独立确认项。

## 严格的数据口径

时间切换只改变**经营概览单元**的读取范围，所有金额继续以分存储并仅在展示时转换为两位小数。时间边界使用现有 `businessDate()` 的设备本地业务日期，避免 UTC 零点造成跨日。

| 指标 | 计算方式 | 日期归属与边界 |
| --- | --- | --- |
| 净营收 | 销售收入 + 其他收入 − 退款 | 销售按订单成交日；其他收入按分录发生日；退款按**实际退款日**。退款不会倒灌到原订单成交日。 |
| 总成本 | 销售成本 + 经营费用 | 仅纳入已入账分录，按各成本分录发生日进入所选范围。 |
| 经营利润 | 净营收 − 总成本 | 与现有统一账本 `buildMetrics()` 相同，范围仅由筛选后的已入账分录改变。 |
| 成本率 | 总成本 ÷ 净营收 | 净营收小于或等于零时不显示误导性的百分比，改为 `—` 并提供短说明。 |
| 经营利润率 | 经营利润 ÷ 净营收 | 同上；负经营利润应保留负号，且以“亏损”文本明确语义。 |
| 订单数与客单价 | 所选范围成交订单数；订单成交总额 ÷ 订单数 | 订单数和成交额均按订单成交日，不因后续退款改变销售日统计。 |
| 退款影响 | 所选范围退款金额及退款笔数 | 仅统计退款日落在所选范围内的退款，明确显示为“退款影响”。 |
| 对比变化 | 当前经营利润 − 对比区间经营利润 | 结果旁显示与范围匹配的比较标签，不再固定写“较上月”。 |

## 范围作用边界

为避免用户认为所有页面模块都被一个筛选器同时改写，建议明确如下。

| 首页模块 | 是否跟随主卡范围 | 原因与显示要求 |
| --- | --- | --- |
| 主结果、等式、成本率、利润率、对比与优先行动 | 是 | 共同构成一条经营结论，必须共享同一范围。 |
| 订单数、客单价、退款影响三项补充指标 | 是 | 紧贴主卡，若不随范围更新会造成数字口径冲突。 |
| 销售额／订单数趋势图 | 否 | 继续独立标注“近 7 日”，保持其订单成交日趋势语义和已有下钻。 |
| 月销售目标 | 否 | 始终是自然月目标，标题继续明确“月销售目标”。 |
| 经营提醒 | 否 | 预算、成本卡和售后提醒具有各自的业务周期，应保留明确入口，不伪装成范围内统计。 |
| 宣传轮播 | 否 | 产品宣传不属于经营数据。 |
| SKU 销量／利润排行 | 首版不跟随 | 保留清晰的“本月”标签；如后续需要，可作为独立的排行范围而非继承主卡。 |
| 最近动态 | 否 | 维持“最近”的按时间排序和最多三条原则；未来可另加“查看本范围流水”入口。 |

```text
┌──────────────────────────────────────────────┐
```

当所选范围没有已入账流水时，不显示“0 元经营利润”作为正向结果，而显示“该范围暂无已入账数据”，保留“记一笔”与“记录订单”两个真实入口。若仅有成本没有营收，则应真实显示亏损金额、总成本及比率不可计算状态，不应套用空态。

## 最小实现与验收边界

确认后，实施将新增一个纯前端范围解析与账本筛选层，复用现有的 `buildMetrics()`、订单与退款对象，不修改 `BookState`、订单归集、退款建账、SKU 聚合、金额精度或历史快照。推荐把选择状态保留在首页 URL 查询参数中，以保证刷新和浏览器返回时范围一致；不需要数据库迁移。

验收会覆盖今天、本周、本月、跨月自定义、无收入、有成本、亏损、退款跨日、订单跨日、月末和不同设备时区，并在 375、390、430、768、1280px 与三套皮肤下复核。时间切换不会改变销售趋势的 7 日成交日口径，也不会把退款改写到销售日。
